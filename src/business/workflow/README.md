# src/business/workflow：业务流程编排层，只选下一步并调用一个核心 owner

## 负责什么，不负责什么

- 负责业务流程：`advanceWork` 按已采纳的 Goal/Plan 选下一步，每次 `perform` 只调用一个 owner，并把 owner 的完整结果作为 `receipt` 交回 Host；另提供初始规划、request intake、归档、维护、决定、咨询、活动回填入口，以及 Host wake loop 驱动的两条请求队列处理器。
- 允许依赖 `WorkGraph`、`AgentRuntime`、`WorkspaceTools` 和 `src/contracts`；不得 import `RecordStore`、`src/app`、`src/composition`。
- 只选择流程意图与顺序；存储、索引、状态机、读取器都在 `src/core/work-graph/`，本层不得重写，也不保存 Workflow 数据库、去重表或第二个控制循环。
- 状态迁移只交给 `src/core/work-graph/state/`，本层不得直接改受保护字段（根 AGENTS 第 9 条）。
- 不负责：Host 路由与接线（`app/`、`composition/`）、记录编解码、Task/Goal 完成裁决（`tasks/completion.ts`）、UI 读模型（`views/`）。

## 内部用

- `workflow.ts`：`ownContext`（本层入口共用的可信 Host 上下文绑定）与模块级构造器 `graphWrite`、`prepareStep`、`settleReviewStep`（第四个参数 `adviserAvailable`，缺省假）、`cancelReviewRoundStep`、`requeueTaskStep`、`reverifyRoundStep`、`readyValue`、`waiting`（供 `task-gate.ts` 装配）；`activity-backfill.ts`：`ACTIVITY_BACKFILL_BATCH_RUNS`（默认批大小 5）；`consultation.ts`：`hashOf`（message ref 的规范 sha256，重放身份与 Query 指针共用）。

- `decision-actions.ts`：`createActionReleaseApplicationAdapter`（G 的 `action_release` 卡第②步适配器：按答案派生 `commandId` 交 `approve`/`deny`，已放行且无 `notSent` 时经同一个 `deliverStop` 送停，提交回执作第③步）；`intervention.ts`：转出 `INTERVENTION_CLOSING_REASONS`（干预收尾的固定理由，`questions` 不发通知）与 `interventionClosingNoticeRequestId`（收尾通知的确定性 `requestId`）；`contracts.ts`：转出 `PLATFORM_NOTICE_ACTOR`（Host 自动收尾通知的唯一固定平台身份，发送和 `closingNotice` 回执读共用，不是 `SYSTEM_ROUND_ACTOR`）；三者的正本都在 `contracts/core/session-message.ts`（`src/contracts/core/session-message.ts:150-170`），Workflow 和 WorkGraph 读同一份。

## 不要做

- 不要直接 import `RecordStore`、`src/app`、`src/composition`，也不要另写存储、索引、状态机或读取器；本层只选意图，执行与结果交给核心 owner。
- 不要绕过 `src/core/work-graph/state/` 改受保护字段；Session/Goal/Task/Run 的生命周期写入各有 owner（AGENTS 第 9 条）。
- 不要另写 oldest-pending 或容量规则：`oldestPendingRound` 已合成一份正本（`src/core/work-graph/queries/request-rounds-read.ts:464`），本层 `oldestPending` 只是私有包装；容量由 Session 目录的计数准入判定（`seatAtCap`，`src/core/work-graph/sessions/allocation-read.ts:35`），本层不另算（M1-16、M1-18、MH-24、FP-12、MH-12）。
- 不要跳过 `findLine` 直接新建线，也不要假设新建 Session 的 revision 仍是 1；重试先按 `commandId` 查回原行并读当前 revision（MH-03、FP-13）。
- 不要另写 rejection 构造：用 `src/contracts/core/rejections.ts` 的 `rejected`/`rejectedWithCurrent`，本层只保留 owner 专属文案（M1-29）。
- 不要把 `advanceWork` 改成有状态循环、调度器或第二内核：每次只调一个 owner 并保留其完整 receipt；`waiting`/`completed` 必须 `next: null`。
- 不要在 `request-round-queue.ts` 里读记录库或重算规则：它只经注入端口（`rounds`、`facts`、`sessions`、`profiles`、`drain`、`driver`）工作，选轮用 `oldestPendingRound`、Session profile 用 `forSession`、页上限取 `src/core/work-graph/model/request-contracts.ts` 的常量、退避毫秒数取同文件的 `backoffMsFor`（不要内联第二份公式）；队列也不做第二个调度器，唤醒只来自 `wake` 与注入的 `settle()`。
