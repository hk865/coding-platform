# src/ui/：画板运行时和接后端的页面

这一层把 `docs/ui-reference/workbench-2026-10/*.dc.html` 跑起来：读画板自己的模板和逻辑脚本，用画板自带的示例数据渲染，交给现有 Host 的静态目录。十块冻结画板里 `ArchOverview`、`Chain`、`Decide`、`Done`、`Main`、`Plan`、`TaskMap`、`Goals` 和 `Member` 有工作副本（`src/ui/boards/`），其余仍按冻结原件构建（E3-2 裁定 1、E3-NAV §1.2）；冻结后新加的设置页 `Settings` 只有工作副本，构建时和十块一起放进 `dist/app/public/workbench/`。`ArchOverview`、`Chain`、`Done`、`Main`、`Plan`、`TaskMap`、`Goals`、`Decide`、`Member` 和 `Settings` 这些块接后端：`boot.ts` 读平台令牌，经 `host-client.ts` 走同源路由，`TaskMap` 用 `adapters/task-map.ts`、`Main` 用 `adapters/main.ts`（导航段用 `adapters/nav.ts`）、`Plan` 用 `adapters/plan.ts`（中栏复用 `readMainThread` 和 `adaptMain`）、`Goals` 用 `adapters/goals.ts`、`ArchOverview` 用 `adapters/arch-overview.ts`、`Decide` 用 `adapters/decide.ts`、`Member` 用 `adapters/member.ts`、`Chain` 用 `adapters/chain.ts`、`Done` 用 `adapters/done.ts`、`Settings` 用 `adapters/settings.ts` 转成 `props.data`（结构开关按当前项目的 `saved ?? defaults` 画，命令审查线画生效分钟数并存整数、清空回默认），入口在六块有左栏的板的左下角（带来源页的全部查询参数，`Esc`/“返回工作台”回原页），写口 `saveSettings` 用回答里的新快照重画；Host 回“已保存、尚未确认”时先重读一次快照再画，那一块写“已保存，尚未生效”并给“重试”；没有令牌时任务图只显示空壳（“这个项目还没有目标。”），其余各块照旧用示例数据（裁定 3、4、6、7、8）。

计划页和交付页共用 `readPageAux` 和 `saveFile`。保存用编辑起点的文件摘要，版本冲突可比较磁盘内容、重新载入或确认覆盖。单个文件读失败只在文件内容区提示。保存失败显示在该文件的保存按钮旁，下一次点保存时清除。发送失败显示在发送按钮旁，两页都在下次发送时清除，计划页成功重读后也会清除。

## 怎么跑

```sh
npm run build          # tsc，然后打包 support.js 并复制画板
node dist/app/main.js <workbench-config.json>
```

打开 Host 打印的 `/workbench/` 地址，入口页列出十块冻结画板和设置页（共 11 块）。测试用 `npx vitest run tests/ui --maxWorkers=2`。

- ArchOverview 的空状态：没有采用的目录时页面写“还没有采用的架构图”，没有观测时写“还没有观测结果”并保留声明层模块；`tasks/query` 的 `not_found` 是“没有计划”，不写“找不到这个目标。”。
- E34 的轨道读：打开轨道后 `readMore({track:true})` 让 `boot` 按 `cursor → next` 读完 `activity/track`（无过滤的 Work/check，再按 ≤33 个唯一 `chainSessions` 分批读 Query，按 `queryRunRef` 去重），并按完整页读 `executions/list`（每页 100）；首次回放读 `tasks/timeline`（每页 200 个 Task），归档展开读 `lines/archived`，选中线读 `lines/read`。这些读取走同一个刷新环，不另开轮询；打开的轨道在每次通知后重读当前窗口。
- E34 的日历读：打开轨道时 `boot` 按浏览器 IANA 时区读 `activity/calendar`；小时窗 ≤14 天（与板的 14 天长历阈值同一判断）、日窗 ≤400 天、没有游标，更长范围拆窗，全部窗都读完才算完整；任一窗失败走既有 stale/失败路径，不当空日历。日/小时身份只用返回的 `localDate/localHour/startAt/endAt`。
- E34 的详情和第一个写动作：`adaptTaskMapDetail` 只把已读的 `graph/detail` summary/participants/risks（risks 成“重叠”，最多 6 个）、可选完整计数、正式目录（计划模块和实际文件的分组；计划写了文件就按文件：每个文件一行“计划要改”，改过的写“计划要改 · 实际改过”，清单外的标“不在计划里”；没写就按模块对计划：既不是计划模块、也不在计划模块下面的标“不在计划里”，计划没有模块时不标）、`files/uncommitted` 的值（实际文件的加减行和“未提交”，E3-7）和任务行的 `dispositionChange`（处置句，计划时间取那一版的 `acceptedAt`）、`attemptOrdinal`（负责是一条线时接“第 n 次尝试”，“未分配”不接）转成详情；`boot` 在选中节点时经 `props.actions.readMore` 读它，读详情时再按实际文件的路径读 `files/uncommitted`，读失败只是不写数，`host-client.write` 发 `{scope,request:{input,meta}}`，`pinLine` 先读 `workspaces/registration` 再提交 `lines/pin`，结果只看 `committed`（裁定 7）。任务摘要的 §2.8 四项也由同一个适配器转：`holds` 每条一行（谁/理由/失效规则/已撤销或已失效），`holdRelease` 只在可用时给“撤销暂缓”（走 `releaseHolds`，一次撤掉这个任务的全部原因；`boot` 把这次 TaskMap 读的工作区 scope 记在 `TaskMapData.scope` 并交给 `publish`，`releaseHolds` 用它发 `{taskRef}` 和空 `expected`），`dispatch` 给请求时计划版本、已由哪条线领取及领取时的计划、作废原因、现在不能领取的暂缓/门/节点占用/线忙原因（`targetLoopBlockers` 是 `not_read` 时不编原因），`stop` 给叫停各步和没送原因；`cardStatus` 是同一批事实的短句，任务卡的状态行和详情头用它；派活卡等时写“平台会照常安排领取，领到后这张卡自动关闭”，叫停卡等时写“先答卡、暂不领”。
- E3 Done 的读：`readDone` 先按 `readNav` 读导航段（传 `boot` 和整个 demand，`archive` 照传），再按 §2.2 的顺序读 `completion-policies/read`（`not_found` 是合法空态）、一个 active gate（目标级优先，其次唯一的；多个且无目标级写“有多个验收关口，还没接通”）的 `verification/round`（`not_found` 是 `no_round`）、完成的目标再读一次 `goals/delivery`（Goal、当前 GoalPhase 版本、确认记录、节点行和秘书；读失败只灰交付卡三个动作，五段照画）、`architecture/change-scope`（失败整次读失败）、每个 Task 一次 `graph/detail` 只取 `actualFiles`（同一 Task 的路径按路径去重）、`architecture/change-scope` 的每个路径按它自己的 workspace 分组（canonical 路径经 `splitWorkspacePath`）并经 `uncommittedPagesOf` 每 100 条一批读 `files/uncommitted`，与 TaskMap 详情共用这一段读（TaskMap 总上限 100，Done 不设总上限；失败只让该工作区的数字为 `—`）、去重后的 `executions/read` 和带 `requeueRef` 的 `executions/brief`、每 200 个 Run 一批的 `activity/runs`，最后只在页面点名 digest 时读一次 `materials/open`（失败只置 `reportError`），再读右栏当前页签（`readPageAux`，收起时不读）。`cursor` 是第一步的 `changesHead`。
- E3 Member 的读：`readMember` 先按 `readNav` 读导航段（`goals/list`、`lines/list`、`goals/display`、`decisions/queue` 和选中线的 `lines/read`；URL 的线不在了就保留左栏、只丢线），再读 `lines/page` 的 `executions`/`messages`/`copies`/`participation` 四段第一页（每段 `limit:100`，不按 `nextCursor` 翻页）；对当页每条消息读 `messages/view` 和 `messages/body`，对当页每条副本读 `queries/read` 和最后一答 `queries/answer`；线自己的任务不属于所选目标时按它的 `TaskTriple.goalRef` 再读一次 `tasks/query`；当前执行（最新 `running`/`starting`，否则最后一条 `ended`）读 `executions/read`，有 `intentRef` 读 `controls/read`、有 `requeueRef` 读 `executions/brief`；再用这次执行的 `workspaceSnapshot.workspaceId` 读 `executions/steps`（首读 `{ref, after:null, limit:50}`；页面内按 Run 记一份，结束的 Run 刷新不重读，在跑的每次页面刷新从 `runningFrom-1` 续读并按位置合并，展开期间另有 `boot.ts` 的 5 秒续读；`next` 非空可“再看 50 步”，思考被截断时给“看原始记录”，通知记录链到 Chain），记录里的 Run 展开体和别的线的线视图共用 `runStepsOf` 与头行/时间 helper（不再写 `NOT_CONNECTED_TEXT`）；快照里没有的已画 Run 不读、不猜范围；一个 Run 的 `executions/steps` 读失败只让那一块写 `pageTextOf` 的句子并记原始失败，`executions/running-commands` 读失败只让在跑的命令步不画长命令那行（没有分钟数、没有停止，A1 的“进行中”仍在；已结束命令的 `通过，n 秒` 等照常），页面其余照常；有目标时最后读 `graph/hover`；`cursor` 始终是第一步的 `changesHead`。两个页签按需读：点“轨迹”传 `readMore({traceOpen:true})` 读线头 Session 的 `sessions/history` 首页，点“改动”传 `{changesOpen:true}` 读 `files/list` 和前 100 个路径的 `files/uncommitted`，关掉传 `false` 撤回，切回不重读。M32 仍是“部分”（§2.10）：只画工作区未提交文件的真实 path/加减行，不按线聚合、不用 `plannedFiles` 冒充改动，`files/list` 的 `partial` 写“只列了部分”，`not_git` 照实写。`readMember` 每次另读一次整个工作区的 `role-lines/read` 给左栏卡上的建它的（读失败只少这一行）；打开一条 Run 记录时按 `memberRunHosts` 读一次 `network/read`（关详情或换行传 `null` 撤回）。

## 候选卡、停止卡和落实重试

- Decide 和主对话刷新队列时，分别读每张待决候选的 `plans/proposal` 和 `decisions/candidate-card`。两页都能直接采用。Decide 上点“放弃”后还须在卡内确认。采用只带本次队列里的目标版本，放弃还带候选版本。写失败留在本卡，下一次写入开始时清除。确认步骤的失败提示在返回或再次确认时清除。
- Decide 有动作的停止卡共用一个说明框。打开步骤时预填这一步的说明或原因，可以改写或清空。任务级继续直接带说明，目标级继续、撤回检查、去主对话说均有不带说明的提示。“问秘书”把说明带入草稿，点发送后才提出问题。
- Decide 答复已记上、落实仍待处理时，打开“已答复、待落实”中的原卡。它的“重试落实”重放原答复的请求号、内容和版本。换卡或重新打开页面后只按队列显示状态。重试失败时原因留在按钮旁，再次重试时清除。
