# src/ui/：画板运行时和接后端的页面

这一层把 `docs/ui-reference/workbench-2026-10/*.dc.html` 跑起来：读画板自己的模板和逻辑脚本，用画板自带的示例数据渲染，交给现有 Host 的静态目录。十块画板里 `ArchOverview`、`Chain`、`Decide`、`Done`、`Main`、`Plan`、`TaskMap`、`Goals` 和 `Member` 有工作副本（`src/ui/boards/`），其余仍按冻结原件构建（E3-2 裁定 1、E3-NAV §1.2）。`ArchOverview`、`Chain`、`Done`、`Main`、`Plan`、`TaskMap`、`Goals`、`Decide` 和 `Member` 这些块接后端：`boot.ts` 读平台令牌，经 `host-client.ts` 走同源路由，`TaskMap` 用 `adapters/task-map.ts`、`Main` 用 `adapters/main.ts`（导航段用 `adapters/nav.ts`）、`Plan` 用 `adapters/plan.ts`（中栏复用 `readMainThread` 和 `adaptMain`）、`Goals` 用 `adapters/goals.ts`、`ArchOverview` 用 `adapters/arch-overview.ts`、`Decide` 用 `adapters/decide.ts`、`Member` 用 `adapters/member.ts`、`Chain` 用 `adapters/chain.ts`、`Done` 用 `adapters/done.ts` 转成 `props.data`；没有令牌时任务图只显示空壳（“这个项目还没有目标。”），其余各块照旧用示例数据（裁定 3、4、6、7、8）。

## 可复用的能力

- `parseTemplate` / `parseBoard` / `parseBoardParts` / `holePath` / `isEventAttribute`：只读解析，不依赖 DOM。
- `renderBoardTemplate`：纯模板求值。
- `DCLogic` / `BoardView` / `bootBoardPage`：一块画板的实例、更新、挂载和浏览器入口。
- `asRecord` / `asText`：路由 JSON 边界上共用的值守卫。

## 边界

- `docs/ui-reference/workbench-2026-10/` 的十块画板是冻结原型（决定 35），这一层只读、不改写；`src/ui/boards/` 有 `ArchOverview`、`Chain`、`Decide`、`Done`、`Main`、`Plan`、`TaskMap`、`Goals`、`Member` 的工作副本和一份 `kit.css`。`Decide` 的工作副本只换数据层：模板/类名/布局不动，`props.data` 走 `DecideData`，D15/D29、按目标筛选的 D28 和线级四个运行控制按 121-34 画 `is-off` + `还没接通` + `aria-disabled`；有 `readState` 时右栏不画原型样例（D14）：任务图和架构图留面板、正文只写“还没接通”，不画节点和详情，文件/命令/Diff 三个页签和“新建页签”的菜单项按 121-34 画未接通，没有令牌的静态页照旧是原型样例；`ArchOverview` 的工作副本只换数据层：模板/类名/事件不动，`props.data` 走 `ArchOverviewData`；处数和“改动 n”已接上，`来源文件` 和 A18 的“未改动 n”仍是缺口、显示“还没接通”；`Plan` 的工作副本只换数据层：左栏、主对话、冲突卡、目标卡、方案卡、目标栏、决定卡和输入区由 `adaptPlan`（中栏来自 `readMainThread`/`adaptMain`）来，右栏和线视图仍按原型样例、不读数据层（Plan B 才接）；范围/约束、草稿自治、方案任务项/风险、旧版展开、非 `answer` 主按钮、最近一步和运行步骤按 121-34 画未接通。`Main` 的工作副本只换数据层：导航段（收件箱、目标栏、工作线、线视图、目标栏“为什么”）由 `adaptNav` 来，Main A 再把主对话（`main/read` 的轮次、运行块未接通、引用条、翻页“更早”）、轨迹页签（`sessions/history` 原文）、决定卡（`decisions/queue` 的完整卡、答复型 `decisions/answer`、请知悉“标为已读”）、目标栏动作（重新入队走 `goals/copy-draft` + `goals/copy-confirm`）、发送（`requests/submit`/`requests/ask` + 一次 `requests/read`）和左栏顺序本地重排接到真实读口；Main B 再接线视图（`lines/page`/`messages/view` 的记录、`controls/submit`、`tasks/requeue`、`queries/ask`、`messages/send`、归档只读）和右栏共用区（`aux-panel.ts`/`readAuxPanel`：任务树、架构树、节点详情、文件/Diff/保存、命令页空态“还没接通”）。`Done` 的工作副本只换数据层：五段（验收要求与证据、改动的文件、没有做的、返工与接续、用量）、交付卡和问秘书接 `DoneData`；左栏工作线、九个“在任务图里看”、右栏两张图和样例对话/轨迹按 121-34 或 `sc-if` 关掉，真决定卡改成 `Main.dc.html?goal=` 链接。
- 模板语义只实现这十块画板真正用到的部分：点号路径、`sc-if`、`sc-for`、属性洞、15 种 DOM 事件属性、`ref`；没有 `sc-else`、`slot`、列表 key 或表达式。
- `setState` 是浅合并；每次提交（`setState` 和 `updateProps`）先渲染、就地更新 DOM、跑完 `ref`，再调 `componentDidUpdate(prev)`（上一份 props）。钩子里的 `setState` 走普通路径再提交一次；画板按 props 比较，所以会停（§1.1.4）。
- 浏览器里每个节点按模板位置定键（`sc-if`/`sc-for` 的子节点带自己的前缀），每次提交按这个键就地更新：条件块插入时同一元素保留身份和焦点，每种事件只注册一个分发函数，`value` 写属性，`checked`/`disabled` 只在 `true` 时保留属性；这够本地单页看画板用。
- 只有 `host-client.ts` 碰 `fetch`；平台令牌只从页面 meta 读，进请求头，不进 URL、不写日志、不进构建产物。没有令牌时 `bootBoardPage` 不读任何核心路由：任务图显示空壳，另外九块和 E3-1 的页面一致，用示例数据（裁定 4、E32-5）；`ArchOverview` 的 `token:null` 仍逐字挂原型样例。
- 外部资源只有 Google Fonts；`./support.js`、`./kit.css` 和十块画板由 `scripts/build-ui.mjs` 放进 `dist/app/public/workbench/`，由 Host 现有 `publicDir` 提供。
- 十块画板的清单、Node 侧读取和渲染树序列化只在 `tests/ui/helpers/` 里，不进运行时。

## 怎么跑

```sh
npm run build          # tsc，然后打包 support.js 并复制画板
node dist/app/main.js <workbench-config.json>
```

打开 Host 打印的 `/workbench/` 地址，入口页列出十块画板。测试用 `npx vitest run tests/ui --maxWorkers=2`。

- ArchOverview 的空状态：没有采用的目录时页面写“还没有采用的架构图”，没有观测时写“还没有观测结果”并保留声明层模块；`tasks/query` 的 `not_found` 是“没有计划”，不写“找不到这个目标。”。
- E34 的轨道读：打开轨道后 `readMore({track:true})` 让 `boot` 按 `cursor → next` 读完 `activity/track`（无过滤的 Work/check，再按 ≤33 个唯一 `chainSessions` 分批读 Query，按 `queryRunRef` 去重），并按完整页读 `executions/list`（每页 100）；首次回放读 `tasks/timeline`（每页 200 个 Task），归档展开读 `lines/archived`，选中线读 `lines/read`。这些读取走同一个刷新环，不另开轮询；打开的轨道在每次通知后重读当前窗口。
- E34 的日历读：打开轨道时 `boot` 按浏览器 IANA 时区读 `activity/calendar`；小时窗 ≤14 天（与板的 14 天长历阈值同一判断）、日窗 ≤400 天、没有游标，更长范围拆窗，全部窗都读完才算完整；任一窗失败走既有 stale/失败路径，不当空日历。日/小时身份只用返回的 `localDate/localHour/startAt/endAt`。
- E34 的详情和第一个写动作：`adaptTaskMapDetail` 只把已读的 `graph/detail` summary/participants/risks（risks 成“重叠”，最多 6 个）、可选完整计数、正式目录（计划模块和实际文件的分组；计划写了文件就按文件：每个文件一行“计划要改”，改过的写“计划要改 · 实际改过”，清单外的标“不在计划里”；没写就按模块对计划：既不是计划模块、也不在计划模块下面的标“不在计划里”，计划没有模块时不标）、`files/uncommitted` 的值（实际文件的加减行和“未提交”，E3-7）和任务行的 `dispositionChange`（处置句，计划时间取那一版的 `acceptedAt`）、`attemptOrdinal`（负责是一条线时接“第 n 次尝试”，“未分配”不接）转成详情；`boot` 在选中节点时经 `props.actions.readMore` 读它，读详情时再按实际文件的路径读 `files/uncommitted`，读失败只是不写数，`host-client.write` 发 `{scope,request:{input,meta}}`，`pinLine` 先读 `workspaces/registration` 再提交 `lines/pin`，结果只看 `committed`（裁定 7）。
- E3 Done 的读：`readDone` 先按 `readNav` 读导航段（传 `boot` 和整个 demand，`archive` 照传），再按 §2.2 的顺序读 `completion-policies/read`（`not_found` 是合法空态）、一个 active gate（目标级优先，其次唯一的；多个且无目标级写“有多个验收关口，还没接通”）的 `verification/round`（`not_found` 是 `no_round`）、`architecture/change-scope`（失败整次读失败）、每个 Task 一次 `graph/detail` 只取 `actualFiles`（同一 Task 的路径按路径去重）、`architecture/change-scope` 的每个路径按它自己的 workspace 分组（canonical 路径经 `splitWorkspacePath`）并经 `uncommittedPagesOf` 每 100 条一批读 `files/uncommitted`，与 TaskMap 详情共用这一段读（TaskMap 总上限 100，Done 不设总上限；失败只让该工作区的数字为 `—`）、去重后的 `executions/read` 和带 `requeueRef` 的 `executions/brief`、每 200 个 Run 一批的 `activity/runs`，最后只在页面点名 digest 时读一次 `materials/open`（失败只置 `reportError`）。`cursor` 是第一步的 `changesHead`。
- E3 Member 的读：`readMember` 先按 `readNav` 读导航段（`goals/list`、`lines/list`、`goals/display`、`decisions/queue` 和选中线的 `lines/read`；URL 的线不在了就保留左栏、只丢线），再读 `lines/page` 的 `executions`/`messages`/`copies`/`participation` 四段第一页（每段 `limit:100`，不按 `nextCursor` 翻页）；对当页每条消息读 `messages/view` 和 `messages/body`，对当页每条副本读 `queries/read` 和最后一答 `queries/answer`；线自己的任务不属于所选目标时按它的 `TaskTriple.goalRef` 再读一次 `tasks/query`；当前执行（最新 `running`/`starting`，否则最后一条 `ended`）读 `executions/read`，有 `intentRef` 读 `controls/read`、有 `requeueRef` 读 `executions/brief`；有目标时最后读 `graph/hover`；`cursor` 始终是第一步的 `changesHead`。两个页签按需读：点“轨迹”传 `readMore({traceOpen:true})` 读线头 Session 的 `sessions/history` 首页，点“改动”传 `{changesOpen:true}` 读 `files/list` 和前 100 个路径的 `files/uncommitted`，关掉传 `false` 撤回，切回不重读。三行仍是“部分”（§2.10）：M17/M19 的 Run 展开体只写 `NOT_CONNECTED_TEXT`，不解析 `kernel_session_record_json` 造步骤；M32 只画工作区未提交文件的真实 path/加减行，不按线聚合、不用 `plannedFiles` 冒充改动，`files/list` 的 `partial` 写“只列了部分”，`not_git` 照实写。
