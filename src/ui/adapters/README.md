# src/ui/adapters/：画板数据适配层

这一层只做纯转换：把 Host 路由的返回值变成画板通过 props 读取的形状。不碰 DOM、不引用 `src/app`；除 `line-shared.ts` 经 `host-client` 的几个共用读写入口、以及 `settings.ts` 的设置读写口外，不碰网络（右栏的读在 `src/ui/boot.ts`，lead 11-12 裁定 1）。

## 边界

- 不调用路由、不读令牌、不写日志（`settings.ts` 的 `readSettings`/`saveSettings` 是设置页自己的读写口，只走 `host-client`；快照子集在文件里声明）；`goals/read` 和 `tasks/query` 的读取顺序、导航读的顺序和 `?goal=` 的范围解析在 `src/ui/boot.ts`。
- `goals.ts` 不重算冲突：重叠文件只来自 `goals/conflicts` 的 `objects`，不从两个目标的 `plannedFiles` 求交；两个目标的先后只来自 `goals/list.order`，不解析 `source.key`。
- `arch-overview.ts` 不画几何、不读路由、不判定环（环由页面副本的 `levelEdges` 对已取边自算）；文件 `state` 只表示计划归属，实际改动只在 `touched`/`possible`（来自 `architecture/change-scope`，缺失行不猜）；文件→模块平手时两个 owner 都放，不挑第一个；支撑目录只来自未认领文件的顶层目录，不从 catalog 模块推、不硬编码名字。
- `nav.ts` 不复制后端的判定：目标“未完成”只在 boot 读过 `goals/display` 后判断，归档行只在展开时读；线行不读 chain，`branched` 不冒充一条线。
- 不认识的字段值不做猜测：缺省的任务状态词落在 `pending`；Goal 的状态词只来自 `goals/display` 的 `phase`，没有采用计划时由 `planMissing` 和 `NO_PLAN_TEXT` 表示。
- `adaptTaskMapTime` 不推算：没有正式 `previous` 就不连线；没有 Task 引用的 Query 只落在线上；执行横条带上 Host 给的尝试序号（`attempt.ordinal`）、重新入队的事实（`attempt.requeue`）和失败原因，界面不自己数，第 2 次起才写序号；缺失的历史原因不出现，状态词和时间段照常保留。
- `adaptTaskMapDetail` / `TaskMapNodeDetailData`：`graph/detail` 的 summary 与 participants 页的纯转换；只显示 `actualFiles` 的“实际改过／可能改过”并按 `pathOwnershipOf` 与正式 containment 归组，实际文件不在计划模块（或它的子模块）下时标“不在计划里”，没读到目录时不标；计划写了文件就列出（`plannedFileCount` 给总述），并按文件判“不在计划里”，没写照旧按模块；实际文件同一路径只出一行（有一条 `definite` 就是“实际改过”），带 `files/uncommitted` 读到的“+a −d（未提交）”或“（未提交）”，读不到就不写；总述的后半句是 `filesNote`；负责工作线后面的尝试序号取任务行的 `attemptOrdinal`，第 2 次起才写；计数不完整时只显示参与线。暂缓、派活请求和叫停只读 `graph/detail` 的 summary：`holds` 的 held 且未失效才是当前阻塞，`holdRelease.availability` 说了才算可撤；`dispatch.cardBlocksClaim` 恒为 false，等着的派活卡不挡领取、领取后关闭；`stop.claim==='answer_card_first'` 才写“先答卡、暂不领”；目标循环的门/节点占用/线忙只在 `targetLoopBlockers` 不是 `not_read` 时写，`blockerTextOf`/`holdKindWordOf` 是任务卡和 Decide 的放行卡共用的唯一词表。
- Member/Chain 的共用边界：不解析 Kernel 原始 JSON、不用 plannedFiles 冒充改动、不复制控制项可用性、不复制重新入队可见性。轨迹只列 `sessions/history` 的 `recordedAt`/`kind`/`recordId`（原文才展开，ArtifactRef 写“原始记录”）；改动只画工作区 `files/uncommitted` 的真实 path/加减行；控制项原样用 `kind`/`availability`/`reason`，`expected` 取控制项自己的 `pins`；重新入队只调 `requeueVisible`。

## 候选详情和停止卡说明

- 待决候选的理由和分阶段任务取自 `plans/proposal`，任务分组复用 `plan.ts` 的 `tasksOf`。会装上的检查来自队列卡本身。`candidateFactsOf` 将 `decisions/candidate-card` 的检查缺口、审阅、任务书和降标事实转为详情行。`candidateStaleTextOf` 是各页共用的过期原因词表。`planChecksOf` 供其他计划视图复用草稿的验证要求。
- `noteBox` 只给有动作的待处理停止卡。`DecideAct.wordsField` 决定说明进步骤的 `note` 或 `reason`，为空表示这一步不带说明。主对话的答复框仍由 `hasAnswerBox` 决定。
