# src/app：Host 层——把受信任启动配置装成唯一本地 Host，并提供 HTTP、设置与运行期适配

## 负责什么，不负责什么
- 外层 Host：依赖方向只允许 `src/composition`、`src/contracts` 和 `src/core`/`src/business` 各模块；`scripts/check-boundaries.mjs` 只按模块 owner 判方向，不细化到端口文件。不能开 store，不能被 core/business 反向 import。
- 负责进程外壳：CLI、HTTP/SSE 传输、实例锁、启动 reconcile、Host 设置、提示词包、运行期配置，以及注意力、自动捕获、协作、Goal 扇出和请求驱动（唤醒循环加每 workspace 的两条请求队列）。
- 平台端口：`create-platform.ts` 的 `platform` 对象上的方法都经 `trackedCall`（`src/composition/create-platform.ts:2517`）发布，`close()` 等所有在途调用做完；`secretaryProfiles` 也在发布端口里（`forSession` 是同步查表，`forNewLine` 经 `trackedCall`）。
- 不写状态：任何状态迁移只经 `src/core/work-graph/state/`（AGENTS 第 9 条）；本层只调用平台公开端口。
- 请求体永远不提供 principal、root、token 或凭据；这些只来自受信任的 `options`。
- `src/core`、`src/business` 不得反向 import 本层。

- `wake-loop.ts` — 请求队列和生命周期队列的唤醒循环：按（workspace, queue）合并脏标记，一次一个 pass，`more` 让出事件循环后再跑，整圈无进展即停到下次唤醒，处理器失败 1 秒翻倍退避到 60 秒，commit notice 按项目唤醒订阅了该聚合类型的队列（`register` 的 `aggregateTypes`，缺省是 `QueryJob`/`QueryRun`/`Session`），未武装的 workspace 只认 `request_command` 或 `release_armed`，`close` 中止自己的 `AbortSignal` 并等运行中的 pass。生命周期队列的键是 `LIFECYCLE_QUEUE`、订阅 `LIFECYCLE_WAKE_AGGREGATE_TYPES`（含 `CoreOperation`、`SessionActivity`、`PlanProposal`、`Goal`、三个注记类型，以及唤醒参谋队列 drain 的 `GoalPhase`、`ProjectRoleLimits`，和唤醒冷启动 `coarse_split`、`proposals` 的 `ArchitectureProposal`，以及知识写落盘之后那次完成提交的 `KnowledgeWrite`：同一趟里别的事有进展时，读架构被闸门拒（写还没落盘）的探索被跳过，循环停下、不走退避，写落盘后靠这次唤醒把它带回来）：`createHandoffQueue` 的 `run` 一次跑完整趟（先结束待处理的轮，再把每个未完成操作各继续一次），按种类分派 `continueHandoff` / `manualArchive`，`close` 等它启动的调用；`run`/`pass` 回 `{ continued, blocked, queue }`，`queue` 是这一趟最后那一页参谋队列 drain 的 `GoalDrainResultV1`（关闭后为 `null`），lifecycle `drain` 的 `more` 取 `queue.more`；`notReady` 把任何非 `ready` 的读结果转成带 code/reason 的失败（不折成空结果），交给循环的退避重试。L 的 lifecycle `drain` 在这一趟之后按 `findSessions({includeArchived: true})` 分页（200/页），对 `availability === 'unavailable'` 的每条线用 `hostNotices` 的 `disconnect` 事实包调 `announceDisconnect`；干预被领取后、`collaborationDriver.start` 之前调 `announceInterruption`（两者的工作区取认领结果的 `claim.workspaceId`：被认领任务的 Goal 可能在另一个工作区，不是消息的）；两条都只经 `host-notices.ts` 的 builder，不另开队列、不另判 gone。
- 7D2 XA：第二个工作区的 `workspace_join` 由现有的工作区生命周期循环驱动，`continueUnfinished` 按 `role_line` 把它交给 `roleLineOperations.continueOperation`；不新增扫描、队列或提交后的创建者，`addWorkspaceState` 的 `wakeLoop.addWorkspace` 原样。

### 配置与设置
做 Host 设置、模型/工作区配置和运行期热替换的去这组。
- `host-settings.ts` — 设置后端：目录、模型、检查、自动化、资源上限、Work Run token 预算、提示词包；私有快照推送。模型保存走 `models/save` 的 `promptPack` 字段，选模型走 `models/select`；`run-budget/save` 保存 1…600000000 的整数或 `null`（恢复 400000000 默认），坏值按现有 `invalid` 形状拒绝且不写文件，写失败回滚内存值。`plan-loop-limits/save` 保存 §10.3 的完整 schema-1 双四档表（键齐全、正安全整数、逐档二倍线不低于提醒线、倍率至少 1、两个阶段预算合法）或 `null`（删掉保存键、恢复 `DEFAULT_PLAN_LOOP_LIMITS`）；缺键的对象和非法值都按 `invalid` 拒绝、不落盘、不补默认；存下的值非法时启动失败，不回退不迁移；写失败回滚内存值。`command-review/save` 保存项目审查线的分钟数：正整数（无上限）或 `null`（删掉保存键、恢复 `DEFAULT_COMMAND_REVIEW_LINE_MINUTES` = 60），坏值（0、负数、小数、字符串）按 `invalid` 拒绝、不落盘，存下的值非法时启动失败；Host 立刻装进心跳的到线检查。`knowledge-local`（body `{projectId, workspaceId, localOnly}`，KLS-2“架构图和注记只留在本机，不进 git”）经 Host 的 `knowledgeCheckout` 拿检出（body 里没有路径），不是 git 回 `unsupported`；是 git 时先经 `applyKnowledgeExclude` 改 `<git-common-dir>/info/exclude`，成功才改设置文件顶层的 `knowledgeLocalOnly`（按检出键，不按项目；空表不写这个键），再推私有快照（`knowledgeLocalOnly` 也在里面）；写设置文件失败时回滚内存值，并把忽略文件改回这次调用之前的状态（这次没改它就不动），再回 `unavailable`；改回也失败时原因里两件都写。`WORKSPACE_REMOVED_REASON` 是“已移出”的登记原因，Host 恢复和私有重开共用这一句；`workspaces/access`（body `{scope, writeAllowed, commandsAllowed}`，成功回 `{settings, bootstrap}`）改一个已登记工作区的写和命令授权，命令要先能写；写设置文件失败时整个退回内存里的工作区清单并让 Host 恢复这次之前的值，通知失败回“已保存，Host 配置未确认，请重试同一次保存”。`structural-approval/save`（body `{projectId, value}`，121-109 结构改动自动批准的两个开关 `proposals`/`repairs`，`value: null` 回出厂默认）只给这台 Host 开着的项目存（没开回 `not_found`），值只过 `structuralApprovalOf`（恰好两个键，各是 `auto` 或 `ask`），存进设置文件顶层的 `structuralApproval`（按 projectId；空表不写），再推私有快照；写失败回滚内存值；存下的表坏了启动失败。Host 建平台时给 `structuralApproval(projectId)`：现读最后一份私有快照，这个项目没存过就用 `DEFAULT_STRUCTURAL_APPROVAL`（两个都 `auto`）。检查校验 `validRegisteredCheck`（`src/app/host-settings.ts:458`）同样用 `isPlatformReservedCheckId` 拒绝保留 id `platform:witness`：`checks/approve`、保存答案的提议和启动读回的已存检查都走它。
- `host-settings-types.ts` — Host 本地设置 DTO（请求/响应形状）和 Work Run token 预算的默认值/上限常量，不构成 Agent 工具或领域写入；公开快照的 `workRunTokenBudget` 给出 `saved`、`effective` 与 `max`。公开快照的 `planLoopLimits` 给出 `saved`、`effective` 与 `defaults`，嵌套表按深副本发布，不与保存值或默认表共用可修改对象。公开快照的每个工作区带 `knowledgeLocalOnly: boolean`（按它当前检出的键查，不是 git 恒 `false`）；顶层不加键。公开快照的 `structuralApproval` 给出 `saved`（按 projectId 存下的两个开关）与 `defaults`（出厂默认，两个都 `auto`）。

- `taskbook-export.ts` — 任务书导出（§5.3.4）：`exportTaskbook` 写一个阶段，`exportTaskbooksForPlan` 整批写（写前把真实导出根与每个真实 workspace 根比对，命中就整批失败），`exportBooks` 是只读探针（读回 `written`/`incomplete`/`missing`）。导出永不抛错、不阻塞采用：没有设置目录是 `skipped`，缺阶段或 fs 失败是 `failed`，文件就地覆盖、没有清单/临时文件/回滚/重试。

## 不要做
- 不要在 Host 里实现领域规则、直接读写 RecordStore 或另建服务图；只调用 composition 暴露的公开端口。
- 不要从 HTTP body 取 root、token、凭据或 store 路径；ctx 只由 `createHostCoreCallContext`（`src/app/core-call-context.ts:17`）构造。
- 不要发布绕过 `trackedCall`（`src/composition/create-platform.ts:2517`）的异步 Host 端口：平台端口（含 `secretaryProfiles`）都经它发布，`close()` 等在途调用做完；没 drain 的调用会落在已关闭的 store 上（MH-07）。
- 路径校验不要混用：`isPathWithin`（`src/app/prompt-packs.ts:31`）是真实路径包含判断（`preparePackWriteTarget` 也用它），不是词法副本；源相对路径的词法规则用 `isSafeSourceRelativePath`（`src/core/workspace/path-validation.ts:3`）。
- 不要另写 duty 判定：用 `createSessionDutyResolver`（`src/composition/session-duty.ts:51`）；`forSession` 只按 workspace 与完整 `sessionRole` 查 profile，不做 duty 判断（FP-02、MH-01）。
- 不要只改 Host 选项的类型或消费端：声明、校验、转发、adapter 构造与重开路径都要接上（FP-15、MH-02）。
- 不要假设未配置的 secretary/wake 有默认实现：默认 profile 返回 null、`wake` 为 no-op；容量按 `ROLE_LINE_DEFAULT_LIMITS` 的默认上限判定（FP-12、MH-12）。
- 请求驱动只在持实例锁且 `requestDriver` 不是 `'off'` 时装配：`'off'` 时既不建唤醒循环也不建请求队列，提交的轮停在命令留下的地方，等 Query 路由或下一个开着驱动的 Host；测试用手工步骤推进轮时必须用它。请求命令的 wake（平台选项 `requestWake`）和 commit notice 都经晚绑定 sink 进循环，循环从不影响 commit；队列的 `context` 用 Host 的系统 reconcile actor，drain 的 `AbortSignal` 由循环传入。
