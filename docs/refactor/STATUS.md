  - 旧界面仍是生产界面，会把一部分第 5 步的语义显示错。例如：未进入就被取消的 Run、被较新控制取代的控制。

- **本批之后还没有用真实模型重跑过。** 9-28、9-29 的真实模型验收都早于本批，而本批改了消息、Session、领取等服务。
- **接续的三个代价**（决定 7，5.6 落地；第三个在第 6 步核实）：
  - 发给原 Session 的回复，到不了接续用的新 Session；
  - 每有一次这样的中断，就退役一个 Session；
  - 中断之后，接续用的新 Session 里第一个新 Run 能看到原来的历史，同一个 Session 里之后的 Run 只看到这个 Session 自己做过的事（冻结的 Kernel 所限，以后给 Kernel 打补丁）。
- **硬依赖现在只用于显示。** 领取和 Workflow 都不看依赖。“消费时检查精确输入”仍是未完成的 MVP 项（决定 11）。
- **材料授权**：写入部分已删除（2026-10-07），相关文档已改，规格里的授权行已标注。现在没有办法发放授权，所以 Run 读别的 Run 的材料（current）一律拒绝，和以前没发授权时一样。只为授权存在的读取分支还在，随后删除。独立审阅者以后要另想办法读材料。
- **能力文档里还有别的过期条目**，例如 WG5 写着“重入队未实现”，自 b67111d（5.4 提交 `requeueTask` 和 `tasks/requeue` 路由）起已经不对，第 7 步统一更新。2026-10-05 只改了设计核对 §3.18 点名的两处：RT6 的能力上报，WG14 的架构修订。
- **架构图**：
  - 修订服务已有，但没有路由，所以冷启动之后正式架构就不再变；
  - 冷启动时不能声明包含关系，真实项目的图是平的；
  - 没有正式与观测的比较；
  - 除原始路由 `sessions/link` 外，界面、Workflow、agent 和冷启动都不写模块负责人（Session 的模块关联），所以模块负责人一直为空；
  - agent 没有读图的工具。
- **设计核对时读代码发现、还没运行验证的问题：**
  - Workflow 建的 Session 带着“负责某 Task”的关联，所以在工作台上归档会被拒（`dependency_blocked`）；
  - 派生出来的只读咨询 Session，之后可能被同角色的 Work 拿去用；
  - 被取消或替代、从没运行过的 Task，在任务图里读起来像“待执行”；
  - 注意力观察把依赖条件拼成了 `[object Object]`，所以依赖条件变了也不会被当成图的变化。
- 原 Turn 的 fresh resume、原生压缩仍不支持。
