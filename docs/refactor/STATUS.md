## 缺口（对使用者有影响的）

- **第 5 步只做后端**（用户 2026-10-04 决定）。新路由和读模型字段，旧界面都不显示。新界面交付之前：
  - Host 重启后已暂停 Task 的“继续”（5.6）、Goal 级暂停/继续/取消（5.5）、重新检查（5.9）和自动化设置（5.6/5.8）没有界面入口；重新入队已有 `tasks/requeue` 路由，但没有界面。执行页现有的 暂停/继续/取消 按钮只覆盖 Host 存活期间的单个 Run。
  - 旧界面仍是生产界面，会把一部分第 5 步的语义显示错。例如：未进入就被取消的 Run、被较新控制取代的控制。
  - 这些界面项逐条记在 [E3-UI-ITEMS.md](design/orchestration-2026-10/E3-UI-ITEMS.md)（98 条，第 7 步从临时目录移进仓库，按当前代码核对过），随新界面（E3）一起做。
  - 那份文件末尾“还没定的”有 6 条，要在 E3 开工前定。其中第 1 条要用户定：冻结原型让已取消的目标“可重新入队”，后端里取消的目标是终态，也没有目标级的重新入队。
- **本批之后还没有用真实模型重跑过。** 9-28、9-29 的真实模型验收都早于本批，而本批改了消息、Session、领取等服务。
- **上一 Turn 没结束时，“继续”在新 Session 里跑**（lead 决定 LA-1、规格 GAP-50；用户决定 7 接受，5.6 落地）。接续在一个关联原 Session、带入原历史的新 Session 里进行，有三个代价（第三个在第 6 步核实）：
  - 发给原 Session 的回复，到不了接续用的新 Session；
  - 每有一次这样的中断，就退役一个 Session；
  - 中断之后，接续用的新 Session 里第一个新 Run 能看到原来的历史，同一个 Session 里之后的 Run 只看到这个 Session 自己做过的事（冻结的 Kernel 所限，以后给 Kernel 打补丁）。
- **规格 §0.7 写明的另外四项限制**（第 7 步按现在的代码核对过，都仍然成立）：
  - **没有定时调度**（GAP-48）。自动返工和自动重新检查只在推进、驱动启动、Host 启动后的重驱和已有提醒时发生；停在等待的驱动不会因为时间到了自己醒。
  - **“失败后源码是否变化”可能是“未知”**（GAP-49）。没有检查轮次的 Run 级失败，在第一次被拒、平台采集源码之前，这一项如实显示 `unknown`；逐文件的“上一 Run 结束以来改了什么”也没有。
  - **agent 还不能自己返工**（GAP-46）。owner 已经接受 agent 发起的重新入队和重新检查，但本批没给 agent 开这两个工具，Runtime 拒绝不认识的工具名；以后由编排接入。
  - **预算用完后的重新入队比用户原话窄**（G-BUDGET）。只有给更大的预算、新的输入或人附的说明才放行；只改了文件、预算不变的重新入队不放行。原因是预算检查在源码采集之前，也没有 Run 结束时的源码检查点。用户可以重新提出（规格 §4 G-BUDGET）。
- **硬依赖现在只用于显示。** 领取和 Workflow 都不看依赖。
- **计划的精确输入现在没人读**（2026-10-07 删除，lead 决定 LA-11）：
  - 准备阶段按计划“精确输入”读材料的路径已删除。
  - 计划如果给某个 Task 写了精确输入（`inputRequirements`），这个 Task 现在照常启动，只是不带这份输入，agent 也不知道有这份输入。以前它会被拒绝启动，停在等待。
  - 真实模型的记录里没出现过这种计划。
  - 编排设计（决定 34）的第 3 片会重建“消费时检查精确输入”；这仍是未完成的 MVP 项（决定 11）。
- **材料授权**：写入和只为授权存在的读取分支都已删除（2026-10-07），相关文档已改，规格里的授权行已标注。现在一个 Run 只能读自己的材料，而且不能按“当前”读；读别的 Run 的材料一律拒绝，和以前没发授权时一样。取得来源版本（source pin）的两个文件保留、不接线，编排设计第 3 片可能要用。独立审阅者以后要另想办法读材料。
- **每个 Task 的证据条数没有上限。** 契约里原来有个上限常量（512），但从没有代码检查它，2026-10-07 随简化 G7 删了。自动返工有次数上限（默认 3 次，最多可设 10 次），实际使用中证据条数因此有限；人手动重新入队或重新检查不受这个上限。按简化清单，不另接证据上限。
- **架构图**：
  - 修订服务已有，但没有路由，所以冷启动之后正式架构就不再变；
  - 冷启动时不能声明包含关系，真实项目的图是平的；
  - 没有正式与观测的比较；
  - 除原始路由 `sessions/link` 外，界面、Workflow、agent 和冷启动都不写模块负责人（Session 的模块关联），所以模块负责人一直为空；
  - agent 没有读图的工具。
- **设计核对时读代码发现、还没运行验证的问题：**
  - Workflow 建的 Session 带着“负责某 Task”的关联，所以在工作台上归档会被拒（`dependency_blocked`）；
  - 派生出来的只读咨询 Session，之后可能被同角色的 Work 拿去用；
  - 被取消或替代、从没运行过的 Task，在任务图里读起来像“待执行”；
  - 注意力观察把依赖条件拼成了 `[object Object]`，所以依赖条件变了也不会被当成图的变化。
- 原 Turn 的 fresh resume、原生压缩仍不支持。
