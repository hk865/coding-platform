# 011 命令联网：主机记在每个 Run 的一份记录里，连之前写；代理在 Host 进程里，只收 CONNECT 和 http:// 完整网址

状态：采用（NET-B 第一段落代理、地址规则、工具链、记录和读路由、核对证据；第二段接上 Host、Runtime、检查和工作台，提示词改成命令可能联网）
日期：2026-11-13

## 背景和约束

- 121-112：命令能上公网，不做名单和档位；硬线只留“连不到本机和内网”；每个 Run 记下连过的主机。
- 命令沙箱保留 `--unshare-net`，唯一的出口是 Host 给的 unix socket（SBX，取舍 010）。所以“连不到本机和内网”只能由 socket 后面的代理保证。
- 结果未知的核对记录只在 Host 重启之后由启动对账建（RUN-25），人工判定（RUN-22）也是对已结束的 Run。参谋要看到主机，主机必须在 Host 死之前就进库。
- 平台网页带本实例的令牌，Host 的监听地址可以改；内网服务和云元数据都在私网或链路本地段里。
- 网址里可能带令牌，只能记主机和端口。

## 选项

| 选项 | 怎么做 | 好处 | 坏处 |
|---|---|---|---|
| **A. 新记录 `RunNetwork@1`，连之前写（选）** | 每个 Run 或 QueryRun 一份，代理在 dial 之前经 owner 写一条（主机、端口、地址、结论） | Host 崩了也在；结果未知的核对记录建出来时能拷一份给参谋；`network/read` 随时可读 | 每个新主机一次小写入；多一个记录类型和 owner |
| B. 挂到 RunActivity 上，Run 结束时写 | 结束提交里带上代理在内存里攒的主机 | 不多记录类型 | Host 崩了就没有，参谋永远看不到；回填从 Kernel 记录算不出来，替换时还要保留它 |
| C. 只在内存，打一行日志 | 不入库 | 最少 | 121-112 的“记下主机”不成立 |

代理放哪、收什么：

| 选项 | 好处 | 坏处 |
|---|---|---|
| **Host 进程里的 HTTP 转发代理，每个 Run 一个 socket，只收 `CONNECT host:port` 和 `http://` 完整网址（选）** | Run 只由 socket 区分，不靠任何凭据；https、git over https、npm、pip、curl、Node 的 fetch 都走 CONNECT；Host 一死隧道全断 | ssh、裸 TCP、SOCKS 不通 |
| 开源 sandbox-runtime 的代理 | 现成 | 要改它才能按 Run 记账、先记再连 |
| 透明代理 / 放开沙箱网络加防火墙规则 | 不限协议 | 要改宿主网络、要权限；本机地址每次都要现查，规则难审 |

## 选了什么，为什么

选 A 和 Host 里的代理。记录在连之前写，所以它就是 121-112 用来代替名单的那道账：没记下的连接不出去（回 503）。代理先解析一次，逐个判地址，连的是查过的那个 IP，不再按名字解析，挡住 DNS rebinding。带 IPv4 的 IPv6（映射、兼容、NAT64）按那个 IPv4 判，本机网卡地址每次现读。

## 代价，以及因此要守的规矩

- **地址规则只有一份：** `src/app/command-sandbox.ts` 的 `commandNetworkBlocked`。段表来自 IANA 特殊用途地址表里不可全球路由的段，再加本机网卡地址。
- **只记主机、端口、查过的地址、结论和第一次的时间。** 不记路径和查询串；代理不打流量日志，不带任何凭据，不转发 `Proxy-Authorization`。
- **一条（主机、端口、结论）只写一次：** route 内存里去重，owner 的写入身份就是这三项，重复的回原回执；超过 200 条只计数。
- **核对记录里的 `network` 是建记录那一刻的拷贝（前 32 条）。** 没有这一项表示读不到，不表示“没连过”。
- **全 Host 最多 256 条上游连接**（安全：每条隧道占 Host 两个文件句柄）。
- **登记的检查命令不联网**（协调：验证要能复现，定义是按不联网批的）；人在工作台跑的命令联网但不记（不是 Run）。

## 什么情况变了要重新考虑

- 做名单、档位或提权卡（G6 之后）：判断放在 `admit` 里，记录不变，结论多一种。
- 要支持 ssh 或 SOCKS：在同一个 socket 上按第一个字节分辨，地址规则和先记再连照旧。
- `web_fetch` 的主机也要进这份记录：记录加一个来源字段，发请求前同样调 owner 记一条。
- 命令可能有对外动作、要不要“不自动重跑”：今天 `run_readonly_command` 仍是 `read_only`，主机记录让重发看得见；改分类时参考这份记录。
