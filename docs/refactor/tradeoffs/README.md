# 技术取舍记录

更新：2026-11-10（六篇采用）。用户 11-09 同意（决定 121-70）。

决定的原委写在 [HANDOFF 顶部](../HANDOFF.md)，决定现在是否有效看[决定表](../DECISIONS.md)。本目录补另外三样：当时还考虑过哪些方案、为什么没选、什么情况变了要重新考虑。以后需求变了，先在这里搜相关的篇，看当初的理由还成不成立。

## 什么时候写一篇

- 在几个技术方案里选一个：存储、格式、库、协议、算法、规模假设。
- 有真实备选的产品取舍。
- 包内的小裁定不单独写，照旧记在 HANDOFF。

一篇和它的决定放在同一个文档提交里，决定表的“细节在哪”指向它。改主意时写一篇新的取代它；旧篇原文不动，只改“状态”一行。

## 模板

文件名：`NNN-<短名>.md`，`NNN` 按写成的先后从 001 编号。

```markdown
# NNN 标题（一句话说选了什么）

状态：采用（决定 X）｜被 NNN 取代（日期）
日期：YYYY-MM-DD

## 背景和约束
要解决什么；当时的前提（规模、单机单用户、MVP 范围、已有的决定）。

## 选项
| 选项 | 怎么做 | 好处 | 坏处 |
|---|---|---|---|

## 选了什么，为什么

## 代价，以及因此要守的规矩

## 什么情况变了要重新考虑
尽量写成能量的条件（例如“注记和联系超过 100 万条，图查询超过界面要求的时间”）。

## 来源
用户原话（日期）、决定号、相关规格和代码 `文件:行`、外部资料链接。
```
