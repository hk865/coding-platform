# 014 Diff 页逐行：`files/uncommitted` 回 HEAD 提交号、界面读两次；逐行用 Myers，不用画板原有的 n×m 比较

状态：采用（第二十一批，决定 121-148）
日期：2026-11-18

## 背景和约束

- 用户 11-18 定：右栏 Diff 页逐行看改动进 MVP（决定 121-147）。
- 当时已有的：
  - `files/uncommitted` 列出改动的文件和加减行；HEAD 已经读到了，只是没有返回（`uncommitted-files.ts`）。
  - `files/read` 能按 git 提交读，也能读工作区，读范围、大小、UTF-8 和 NUL 的检查都在它这一处。
  - 画板里有一份逐行比较 `axLineDiff`。它建满 n×m 的表，3,451 行的文件约 1,190 万格；1 MiB 的文件约 3 万行，是几亿格。
- 规矩：同一条规则只在一处；能复用就复用；改动尽量小。

## 选了什么，为什么

- **后端选甲。** 加一个字段就够了，读文件的规则不多出一份。决定 121-97 原话就是“逐行 diff，或者能拿到 HEAD 提交号”。
- **逐行选 A。** B 在真实文件上用不了。这一处偏离了 121-147 的写法（“界面已有逐行比较”），lead 准了（`impl/n1118/lead-rulings.md` P3 Q2）。
- 合并几个工作区的读（Done、任务图）没有单一的 HEAD，另加一个不带 `head` 的 `UncommittedFileListV1`，不编假的 `head`。
- 分段照 git：上下文 3 行，中间保留 6 行以内就并成一段，`@@ -a,b +c,d @@`，删的行在加的行前面，最后一行没有换行时写“（文件末尾没有换行）”。审查时和真实的 `git diff --no-index -U3` 对了 379 组，全部一致。

## 代价

- 画板里的五份 `axLineDiff` 都还在。Main 那份还给冲突的“比较”用，大文件同样会卡，记在 E3-UI-ITEMS D121-148-3。
- 每次 `lineEditScript` 把整张前沿表复制一份存起来，编辑距离接近上限时堆涨约 46 MB；换成定长数组可以降到约 4 MB，结果不变，以后再改。
- Host 的加减行在 25 万格以内用 LCS、不设上限，Diff 页总用上限，可能出现“Host 数得出加减行、Diff 页不画逐行”（E3-UI-ITEMS D121-148-5）。

## 什么情况变了要重新考虑

- 要做“哪条线改的”（`by`）、或者要一次读出很多文件的逐行：考虑乙，或者在 Host 上算好再给界面。
- 改动超过 1000 行的文件变得常见：放宽上限，或者在界面上用 LCS 回走不设上限。
