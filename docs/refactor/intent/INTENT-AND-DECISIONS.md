# 用户意图、已确定行为与工程决定

更新：2026-09-26。本页为接手者解释“为什么这样设计”，可直接阅读；原始对话另存，不要求先读完所有历史。**用户原话、本文归纳和工程方案分别标注**，不能把助手早期意见当用户决定。

## 1. 当前任务及范围

用户希望一个围绕项目数据与工作的多 Agent 平台：核心维护适合查询和更新的结构与原子能力；业务组合这些能力推进任务；架构图、任务图和 Session 关联共同服务检索、编排及人机交互。重构应减少重复扫描、重复准备、重复状态及为旧切分而存在的流程，同时使代码和 UI 更容易理解。

最初设计阶段要求把这一方向写成**足以交给无本次对话记忆的 Agent 的详细骨架文档**：关键文件、内部逻辑、业务决策、完整关键接口、依赖、旧代码去向、失败恢复、验证及接手顺序。2026-09-26 当前已获后续实施授权，在 `coding-platform/next` 按中审、实现、独审和隔离验收逐批完成已确认范围；当前状态见 [HANDOFF](../HANDOFF.md)。不把文档类型或空目录当作已实现。

原话依据：[DLG-047 启动设计](ORIGINAL-DIALOGUE.md#dlg-047-用户)、[DLG-049 追问文件与接口设计](ORIGINAL-DIALOGUE.md#dlg-049-用户)、[DLG-051 要求详细骨架与交接](ORIGINAL-DIALOGUE.md#dlg-051-用户)。DLG-046 是启动请求较早分支版本，原文保留，当前采用 DLG-047 的较晚范围表述。

## 3. 核心概念：接手时直接采用

| 对象 | 含义与保存内容 | 容易混淆的点 |
| --- | --- | --- |
| Role/Skill | 可复用能力、指令、工具和工作规范；使用时绑定版本 | 同配置不等于同一永久人格；可以并行创建不同 Session |
| Session | 可继续的上下文与 Kernel 历史；平台只保存目录、映射和工作关联 | Session 不是一次 Run；复用 ID 也不自动证明历史进入了下一次模型输入 |
| Run / QueryRun | 一次真实执行；后者供有实际模型执行的查询路径 | 普通文件/图/历史读取不需要伪造 Run；Session 占用必须同时覆盖两种执行身份 |
| Task / Attempt | Task 表达工作及完成条件；Attempt 表达一次尝试 | 返工可复用 Task 并新增尝试，不用任务依赖回边表达返工 |
| 架构图 | 已采用职责/接口/依赖与源码映射；同时有观测关系和历史 | 观测 import 环不因目标 DAG 要求而被隐藏；语义标签不冒充确定性代码依赖 |
| 任务图 | 协作白板、当前意图、责任、关系、执行历史及证据入口 | 图不替代 Agent 编排；预期依赖不是硬门槛，明确消费条件按所需产物检查 |
| 工具结果/证据 | 具体执行输出、版本、来源、明确决定及理由 | 命令成功不自动说明任务完成；摘要不把“曾经通过”升级成“现在正确” |
| Workspace/Git | 文件当前状态、未提交差异和已提交历史 | Git commit 图与文件树不同；非代码材料按路径/文本/语义索引，不对所有文件硬套 AST |

“四种基础数据”是用户对来源与时间维度的划分。工程上从中导出八类专用结构，不意味着需要八个顶层模块或八个独立数据库。图关系可以保存正式责任，也可以是重建索引；由字段的用途决定是否可丢弃。

状态循环的例子：`实现 → 检查失败 → 返工 → 检查` 可以反复；事件记录是 `Run1 → Check1 → Run2 → Check2`。消息 A→B→A 是合法往返；明确采用的硬输入前置环会导致互等，应拒绝；预期关联不据此升级为阻塞。墙钟时间前进不能消除这种互等，也不自动说明任务有进展。

## 4. 本轮工程选择：不是用户逐字指定

| 编号 | 采用的选择 | 理由与边界 |
| --- | --- | --- |
| E01 | 五模块：Workflow、WorkGraph、AgentRuntime、WorkspaceTools、RecordStore | 按策略、工作结构、执行适配、文件算法、物理持久分责；数量是推导结果，不是门槛 |
| E02 | WorkGraph 内部保留多组专用组件 | 身份、来源和共同提交需要协调；每组结构仍有独立索引与文件，避免一个大类或万能图 DSL |
| E03 | AgentLifecycle 分为策略、平台状态、实际执行三部分 | 功能保留并落实，取消独立包装模块；材料与历史查询仍可直接使用 |
| E04 | ContextCompiler 的需求选择、材料查询、Kernel 输入适配分别落位 | 六类旧消费者按用途迁移；不把旧全量准备链整体迁成生命周期私有实现 |
| E05 | 保持当前数据库/历史身份，分批移动实现 | 减少并行重构的变量；必要新增 schema 用显式迁移；旧消费者清零即退役兼容层 |
| E06 | 单 Session 一条可修改对话的执行 | Run 与 QueryRun 共用同一个占用约束；独立并行使用不同 Session |
| E07 | 创建 Session 与领取工作分开 | 创建建立稳定 Kernel 映射，尚不启动模型；领取失败不删除先前独立创建的 Session |
| E08 | 外部副作用使用受理、执行、观察三阶段 | 数据库事务内不运行模型/命令；结果未知先核对，不以重试制造第二次副作用 |
| E09 | 核心正式变更是完整操作，不暴露任意改状态 | `completeTask` 校验采用的条件；底层存储有内部事务协议，但不把它暴露成模型万能写库工具 |
| E10 | 普通材料访问支持真实 host 身份 | 使用现有授权与范围，移除无关 Run 前提；不通过伪造 Run 或自报 system 身份放行 |
| E11 | 临时源码捕获与持久来源分开 | WorkspaceTools 不依赖存储；先返回捕获句柄，调用方保存内容后建立持久引用 |
| E12 | Kernel 真实能力逐项核验；历史延续需要最小公开接口扩展 | 当前同 sessionId 的新调用不自动继承历史；采用 Kernel 内部处理历史与预算，平台不再实现另一套历史 Context 管理；具体扩展在 AgentRuntime 设计 |
| E13 | 原生 compact 未实现时返回 unsupported | 配置项、设计目录和预算裁剪不等于压缩；重组/交接可按独立业务操作实现，不冒充原会话原生压缩 |
| E14 | 边界只允许单向源码依赖 | 消息/事件反馈不构成反向 import；端口注入同样算实际依赖；Host 在外层组合 |
| E15 | 原话归档、当前设计、源码事实分别维护 | 原话不因新设计被改写；过去助手建议不自动成为约束；当前源码仍按实际 module-map 判断 |

E12/E13 是详细设计时核对真实 Kernel 后对工程前提的收紧，不是改变“使用 Kernel”的用户决定；它们应作为 R4 的真实接线前置条件。

## 5. 已撤回或不得再引入的推断

- “独立图模块必然是第二个真相源”：不成立，模块边界与事实修改权不同。
- “所有关系必须 DAG”：不成立，只对任务前置与目标模块依赖等具体关系施加约束。
- “核心只能是无领域意义的裸 CRUD”：不采用，核心可以理解 Task/Session 并维护合法性。
- “每次读取必须先走规划、Run、baseline、ContextCompiler 或生命周期”：不采用。
- “已有同 Session ID、Fake adapter 或恢复接口就表示连续 Context 已完成”：不采用，以真实输入和运行验证。
- “少几个模块或少几行代码就证明性能提升”：不成立；用户重视代码与可读性，性能声明仍须有相同输入工作量证据。
- “13 模块/38 边永久固定”：早期对既有方案的讨论被后续按数据和行为重新推导模块的任务取代；新的 5/8 同样不是不可修改的数量目标。
- “不同图只能共享一张存储表，其余均可丢弃”：不采用，专用正式结构与索引按语义分别维护。

## 6. 审阅入口与判据

### 2026-09-23 补充：同一工作区的多 Agent 并行（用户明确决定）

用户本轮原话：“多agent是一定要并行的……一个工作区（项目）里面根据架构图区分了比较开，可以并行的就可以并行……检查应该包含在数据结构的工具当中，由agent，编排agent进行决策/修正，之后再决定是否并行。而不是死板的规则必须限制。（不过要写上注释）”

本条替换此前工程文档“现有工作区单写者约束先保留”的目标选择。产品必须支持同一工作目录按实际范围并行；架构图作为定位、影响分析及分工依据，核心工具负责冲突检查与原子占用，业务/Agent 决定修正和推进。不同 worktree 是可选隔离办法，不是并行的必要条件。实现仍需迁移当前全工作区租约和 Runtime 的 `writeScope='*'` 限制；本条不宣称已实现。

注释：模块分开不保证没有共享文件或命令副作用；同模块也不意味着所有工作必须串行。明确冲突由工具返回具体资源，Agent 修正操作后重新核对，不能用决策文字直接豁免实际冲突。同 Session 的对话状态占用仍适用 E06。数据结构、契约和三种图见 [并行协作设计](../PARALLEL-COLLABORATION.md)。

### 2026-09-24 补充：白板与事前约束的纠偏

[最新用户原话 §4](2026-09-23-PARALLEL-AND-PRODUCT.md#4-2026-09-24任务图不是事前并行安全证明)明确：图主要承载提醒、展示、历史及后续证据查找，不要求 task 确定前证明无并行错误。恢复历史 PRODUCT 的白板定位，纠正“任务前驱完成即启动门槛”和“所有领取预占完整预测资源”的工程扩大。规范、架构和强模型负责语义编排，工具提供已有事实与实际操作结果；权限、原子更新及同 Session 一致性仍保留。当前 next 的 executionDag 被定义为硬边，查询却仅检查前驱整体 satisfied；这一既有语义需调整，不能把旧 PASS 当成最新用户语义已经实现。

### 2026-09-25 补充：原子操作围绕已有图结构复用

用户原话：“我建议以后相关的原子操作实现，多往task-graph和架构图的设计上面靠，这样可以复用已有的结构。开始进行修复，之后继续下一步任务”。本轮历史查找具体采用：任务关联到某次 Run/Attempt，实际进入时记录原 Session 的起点，观察及结束时更新水位和终点，查询按这一定位读取原文。唯一 Session 身份不替代每次执行的身份；已有日志位置主键应由底层读取利用。不能把分别通过的图查询、分页和过滤测试当作完整复用链已完成。

后续原子操作先查任务图、架构图及其内部结构是否已经承载相关身份、来源、关系或算法；在原结构与维护操作中补齐真实缺口，避免另造同义图、状态或扫描。骨架审核同时检查写入维护和查询消费，验收核对实际读取/解析量；确有不同数据语义时仍可使用专用结构，不强制所有能力经过一次图遍历。

### 2026-09-25 补充：完整 Agent 工作路径不得缩成单 Run 接线

用户要求读取[双图、Agent、生命周期对齐文档](../../AGENT-GRAPH-LIFECYCLE-ALIGNMENT-2026-09-25.md)及[编号原话](../../agent-platform-user-replies-numbered.md)，先形成防跑偏计划再实施。前者源于外部讨论，旧13模块资料及未检查源码的缺口判断不能直接覆盖当前五模块；后者保持用户原文，不修改原段落。

采用约束：当前架构图索引正在工作及待命未归档的 Session 工作实体；任务图保留当前/历史责任与执行来源。复用现有 Session、Role 和关联，不建立永久 Agent 主体。生命周期包含角色装配、图绑定、忙闲、控制、连续性、交接与归档；语义选择由角色 Skill/Workflow 提出，正式状态由 WorkGraph 维护，Kernel 副作用由 Runtime 适配。没有模型调用的状态读取及确定性关联更新不触发全量上下文装配。

实施必须列全 A 关联与生命周期、B 真实装配执行、C 通信与角色编排、D 控制连续性/完成/UI。每项分别标识“契约、组件、生产接线、用户路径验收”，不能由测试总数宣布双图或生命周期完成，也不能把尚缺生产者说成单纯缺一条调用。相关工作可延续、独立工作隔离；知识库和长期专家仍只保留明确接入位置，不虚报能力。

### 2026-09-25 后续收敛：生命周期、角色工具与未来任务白板
