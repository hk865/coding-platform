# Session 信息层级收敛（2026-09-29）

用户给出三张 DSH 会话截图，要求简洁、信息隐藏在交互之后、引导自然；本批以现有三栏工作台与双图为结构，调整真实 Session 的阅读与展开，不改后端机制或复制示例数据。

## 主审设计

1. 正文是阅读主线。助手 Markdown 自然铺开；时间、身份为次要信息。运行装配输入不冒作人的对话，`turn.started` 的执行上下文一律默认折叠，短输入也一样。真实 `run.input_accepted` 保持来源区别，不猜是人类发言。
2. 连续过程用一行活动摘要：例如“读取 4 个文件 · 检索 1 次”，下钻才看到工具、技术事件。按真实 adapter + kernelSession + run/turn 和相邻位置分组；正文/输入/来源变化切断组；不重排并行记录。失败/取消/未知须在折叠摘要可见，不冒充成功；没有已知工具时用“执行记录”等中性文字，不能捏造耗时或任务数量。
3. 工具默认是低密度行：动作、目标、状态，失败简述直接可见。参数、输出和完整原记录逐层展开。所有原始 recordId/source/cursor/text 保留可访问与原始顺序，工具全身份关联与未知结果语义不变。不要对整个 UI 建另一套日志数据源。
4. 原记录入口属于消息次要操作，缩短为“原始记录”，通过低对比和 hover/focus 处理信息权重，不能只能靠 hover 才可操作。未知事件原文仍可读。上下文/活动/工具内部原记录不要在默认对话逐条铺开。
5. 已回答成员来信不在历史下面再铺一遍完整消息/Answer/所有引用。保留一行“已回答 / 处理中 / 需要处理”的真实状态和可展开回执，错误或待处理动作清楚可达。常规 settled 提示和历史计数/游标放入细节；缺模型/可恢复/未知结果等需要行动的提示保持可见。
6. 给用户明确“查看最新”入口，复用现有 sessions/history 分页：只读、保留已有前缀、冻结 scope/Session，用户请求后每次最多读取 10 页，仍有更多则允许继续，不能无限扫描或调用模型。页底已读完成时定位最后可见消息；用户回看不被更新强行拖回底部。展开状态在同一 Session 的普通重绘/分页后保留，不跨 Session 泄漏；没有实现服务端反向分页时不要声称已支持。
7. 视觉：中性深色/浅色兼容，无背景图、渐变装饰或卡片墙；聊天阅读宽度约 800px、正文 14px/1.75，留白有节奏。工具过程弱化边框，淡竖线只在展开时辅助阅读。输入框简洁，操作与接收对象清楚；常驻重复说明收成提示。保持页面固定高、内部滚动、输入框与左右分栏可用，窄栏不横向撑页面。
8. Markdown 代码块提供语言标记与按需复制/换行的小工具栏，复制实际代码文本；保持现有安全渲染，不执行 HTML/远程图像/不可信链接。不得为好看隐藏内容永久不可达，长代码内部滚动。已有真实 diff 辅助页保留，不伪造 diff 或把普通输出猜成 diff。
