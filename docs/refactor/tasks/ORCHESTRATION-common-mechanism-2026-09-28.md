## 实现边界与必须复用的能力

- WorkGraph拥有Session、Run/Attempt、Task、邮箱、控制和正式图/回执；使用原RecordStore。不要另建Agent状态数据库或复制一份Task真相。
- Runtime拥有Kernel调用和观察；Kernel保留唯一模型/工具循环及Session历史。Host只机械递送、推进和投影，不作语义调度。
- `session-lifecycle.ts`已有link/archive/reactivate，接真实公开消费者，不重写服务。Session责任关联不是控制授权。
- `workflow.ts`已有owner操作与checks/completion；扩展明确Task/Session意图并保留已有默认选择作为显式选项，不复制完成判定。
- `collaboration-driver.ts`演进为共同驱动，替换原每Goal单currentRun和仅活跃Run outbox wait轮询的限制；同Goal不同Task可独立推进，同Session互斥仍由原owner保证。旧入口可薄适配，但不得保留两份实际驱动。
- Ordinary Kernel工具仍直接执行并在工具内部维持操作边界；不把通用状态机变成每工具全链准入/审批。

## 一致的执行与通信语义

1. 消息用独立字段表达意图（通知、只读问询、行动请求）、需要回复和发送后立即等待。保留原请求/回复来源；旧replyMode=wait可归一到新契约，不保留第二套流程。默认通知不自动变成行动授权。已保存、已递送、实际消费、答复、行动落实分别来自实际事实。
2. 只读问询创建真正隔离的A′：由Kernel从源Session明确的已完成轮次边界重建基线，目标使用独立Session/Run/Turn，保留源引用与边界，后续只写目标。原A可继续运行，不为取快照停A；当前未完成轮次不伪装稳定快照。不是Platform拼文本历史，也不是在原A Session启动Query。Query工具权限继续只读，不能替A作行动承诺。
3. 等待采用明确的Kernel让出事实，与completed、paused、cancelled分开。发送并登记等待后，当前工具组排空，Kernel保存让出边界并退出活动执行；Runtime据观察记录原Run结果并释放该次占用。不能保留轮询工具/挂起模型promise却改UI为休眠。
4. 让出后的普通唤醒在原Session建立新Turn/新Run并绑定原Task、等待和输入来源，旧Run保留yielded事实；不重开旧terminal，不把让出当Work完成，不走checks/Goal完成。Task owner据真实续接条件允许新Attempt；回复重复递送不能创建重复执行。人已暂停/取消或工作被替代则只保存输入，不自动续接。
5. 用户pause与等待不同：pause保留实际暂停的原Turn；明确resume沿原Kernel身份恢复，不换Session冒充恢复。cancel等待真实退出/资源关闭，未知先核对。当前Work控制链可复用，Query也必须接真实控制或明确其实际限制，不能用Work PASS代替Query。控制发送方依据正式Host/Role授权；普通消息、responsible关联或“上级”文本不授控制权。
6. 新输入/steer用幂等来源定位与实际消费事实，在支持的Kernel安全边界进入原上下文；工具组尚未排空不截断。恢复重放不能重复注入。普通来信在适用边界处理，pause/cancel不被通知覆盖；需要执行方向改变时明确指令和实际观察。
7. 所有执行可循环经历工作、等待、继续、再等待；独立工作互不串行。没有来信/变化则休眠，不模型轮询；互相问询走独立A′避免原Session互等。暂停、等待、未知和归档各有真实原因，不能全部归为idle。
8. 重启以原Session/Run/输入/控制事实核对，保留已发生结果；结果未知不重新执行副作用探测。恢复普通消息、已保存回复和原历史的读取不调用模型。明确未进入才可按原身份续办；不靠随机新Session。

## 机械注意力与角色

### 统一输入的具体接缝（已导入，终验资格待收口）

Kernel 的普通执行与原 Turn 恢复共用 `inputSupply`：输入当前 Session/Run/Turn、事件位置及已接受输入 ID，返回带稳定 `inputId`、正文和来源引用的候选。ID 由原消息完整引用及正文/回复部分派生；不以时间、随机值或内容摘要代替来源身份。供给只读，不先标记消费。

在工具组排空、没有活动模型请求的下一次 `before_model` 前，Kernel 沿原 `#commit` 和 required Session sink 保存输入事件，再由 reducer 追加当前 transcript、记录 ID/内容摘要/事件位置。重放与 checkpoint 保留这些事实。同 ID 同内容不重复追加，不同内容冲突；暂停、取消和 deadline 优先。恢复使用原 executionIdentity、原 prepared input、累计 usage、deadline、授权、工具和 cleanup 路径；不选最新 Turn，不用新 Turn 冒充暂停恢复。

平台复用邮箱原正文、回复和来源关联；可信观察者依据已提交 Kernel 输入事件记录“已进入执行上下文”。跨新 Turn 继续时，以原消息关联排除已经交付的来源。**已保存/已递送、已进入执行上下文、业务已处理是三层事实**：provider 失败后上下文仍保留输入，但不声称模型已经理解；Answer、回复或工作产出才支持具体业务处理结论。注意力的业务处理基线不能仅因 `sendMessage` 成功就前移。

注意力扫描不得把自身已排队通知当成新的外部变化而自激；通知重试复用原来源身份。文件读取被拒绝、容量不足或暂不可用保留未知，不当删除；双图读取失败不当空图，统计使用正式节点/关系及来源版本，不用 gate 名等伪边。

心跳只补查原消息位置、文件/图版本及待处理条件。文件变化用新增+删除行量（不能只看净增）；图变化用节点/边/状态差量和涉及范围。阈值、周期、关注范围与最大合并等待来自显式Host配置，没有新变化就不调用模型。重复扫描不累计相同差量，已送达不推进实际处理位置。成员或用户的明确反馈无需等待阈值；平台不识别语义“关键性”。

机械通知进入同一Session输入机制，不新增秘书/参谋/书记专用调度器。职责Skill描述收到这些线索后怎样调查、解释、记录；不默认启动固定数量Agent。更新资源内容必须同步真实runtime-assets摘要。

调查/决定/冲突沿原Query/Answer、Artifact、消息、正式Plan/Catalog和采用回执建立关联；提议不自动成为采用，采用不自动成为落实。需要调整原执行仍走同一输入/控制路径。不创建全局协调者、跨owner假原子事务或新语义验证服务。
