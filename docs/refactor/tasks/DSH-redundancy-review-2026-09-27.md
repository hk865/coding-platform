## 当前设计事实

Agent/角色决定组织、分工与修正；工具负责原子操作，结果反向维护正式图/关联。用户已要求架构/任务双图、多 Agent 协作、必要生命周期，不能因这些消费者尚缺就自动删除既定产品范围。不存在运行中 Role 热切换；不要用直接篡改数据库的状态支持热路径防御。Task 可先有未来意图，Run 结束不等于 Task 完成。历史由 Kernel 保存；已提交事实不应被后续撤权抹掉。正式提交、当前授权、历史事实、只读投影是不同职责。

不要把“代码多”“多一个函数”“错误回到上层”“类型声明存在”“当前缺消费者”直接当冗余证明。分析单位是真实动作及其状态/副作用边界。SQL 读事务 COMMIT 不等于持久化一次校验；固定 Host authorize 是内存操作，不要冒称磁盘瓶颈。未计时不能报性能收益。

## 输出格式

1. 阅读覆盖：已核文件/未核关键路径，是否确实利用了提供的跨模块上下文。
2. 各假设：证实冗余 / 合理分层 / 证据不足 / 正常路径缺失；附最短调用链、文件行号、当前合法生命周期场景。引用必须与源码对应。
3. 每项清理建议说明：合并/删除什么、必须保留什么、删除会损失什么、影响哪些真实消费者。不要给新 Manager/引擎方案。
4. 独立发现和反对主审意见优先；输出 3 个最值得由主审复核的具体点即可。

本报告是候选意见，主审会逐项核实，不自动导入任何生产改动。
