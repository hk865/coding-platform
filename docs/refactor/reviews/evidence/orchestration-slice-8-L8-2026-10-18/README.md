# L8 的执行证据（2026-10-18）：自动抓、请求记录和重试、过时架构提醒

**是什么。** [第 8 片规格](../../../design/orchestration-2026-10/slices/slice-8-SPEC.md)的 L8，在 8D 和 §10 段合入后施工、合入。
- **自动抓：** 工作区登记（根绑定以后）、正式目录采用（初次和每次修订）、正式检查定案为 `PASS` 之后，每次非重放提交发送一次触发；等待中的触发会合并，不保证每次提交对应一次抓取。触发是脱离的，调用方拿原来的回执；每个 Host 一个串行、合并的驱动。没有采用目录时只抓文件层，模块层是空的。
- **请求记录、失败和重试：** 每个工作区一条当前记录，带 `requestSeq`、revision、触发类型和 `requested`／`failed`；失败写属于正在跑的那一轮；下一次 Host 启动（`startup_retry`）或下一个真实触发重试；Host 关闭先停队列、再取消正在跑的那一轮。
- **观测状态的读：** 普通路由 `architecture/observation-state` 按工作区返回最新、上一次和自动抓的请求（带算出的 `pending`）。
- **过时架构提醒：** 准备执行时四类提醒（缺依赖、未声明的引用、没归组的文件、可能移动），最多列出 10 条、超过时另加一行省略说明（总计可为 11 行）、相对时刻、没有观测时的 `还没有观测`。
- **块的工作区范围：** 每块正文都带 `projectId`／`workspaceId`，空块也带；同范围复用；只读新形状（决定 79）。
- 验收行 A-03、A-04、AE1 的自动抓部分和 AE2，以及查源码的回归行；施工和返工中定下的读法见规格 §13。

**结果。** 已合入（2026-10-18，de70ff41）。没有调用真实模型。

## 决定 80 和产品决定怎样改变了轮次

- **决定 80 之前**是施工一轮、返工 1 一轮（Codex 的实现审查和复审）。
- **决定 80（2026-10-18）**改成：一次不限字数的全审、冻结问题表、每轮跑 D1 账本、最多三轮返工。L8 的顺序因此是：全审（`codex/audit.*` 和 `codex/book3.*`）→ 返工 2（整张冻结表）→ 返工 3（剩下的行）→ 返工 4（最后一个）。
