# Codex 审查试验（2026-10-07）

**为什么做。** 用户问：能不能在 DSH 实现之后，换一个模型来审查，再让 DSH 返工？做法是把 GPT 的 Codex 放进决定 36 的循环里。写的人和审的人用不同的模型，免得两边带着同样的偏见。用户同意试，要求推理强度用 high，关键的用 xhigh。

**怎么做。**
- 工具：Codex CLI 0.159.0，随用户的 ChatGPT/Codex Windows 应用安装；模型 `gpt-6.1-sol`。
- 用法：`codex exec -s read-only --ephemeral --json -o <输出>`，加上一段审查说明。说明里让它用 `git show <sha>` 看提交。脚本见 `run.sh`。
  - `codex exec review --commit` 不能附自定义说明，所以没用它。
- 每个用例在一份一次性副本上审，副本检出到那个提交。审完副本都没有改动。
- 三个用例给同样的通用要求，不提示问题在哪。各用例的说明见 `<用例>.prompt.txt`，Codex 的原始回答见 `<用例>.codex-output.md`。
- 在 Windows 的沙箱里，它跑 shell 命令都失败了（`CreateProcessWithLogonW failed: 267`，目录名无效）。它改用自带的 JS 读取工具读文件、跑 git，审查照样完成。

**结论。**
- 3 个用例里，唯一的真问题它找到了，没有一条误报。样本很小，只说明值得放进循环，不说明它能代替 lead 的核对。
- 慢，但可以和脚本核对、lead 读 diff 同时跑，不挡进度。三个用例同时跑，最长的 6.5 分钟。
- 它只看得到给它的东西。要它查“是否照计划做全了”，就要把任务书或计划一起给它（用例 C）。
- 用的是用户 ChatGPT 套餐里的 Codex 额度，不花 Claude 的额度。仓库代码会发给 OpenAI。
