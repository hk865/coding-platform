# 资源上限片的执行证据（2026-10-16）：沙箱命令的内存和进程数上限

**是什么。** [资源上限片规格](../../../design/orchestration-2026-10/slices/slice-RL-SPEC.md)（L1–L16、§2、§5 的 RE0–RE3 和 RL-01…RL-44；施工和验收中的限定见 §9）：
- 沙箱里的每条命令（`shell`、只读命令、检查、工作台工具）套一个 `systemd-run --user --scope`，带内存上限、进程数上限和关掉交换；用看门进程和闸门（fd 4、5）保证命令只在上限生效以后才放行；
- 命令结束后读计数，报“碰到上限 / 没碰到 / 不确定”，碰到时在结果末尾加一句固定的话；
- 机器不支持时照今天的样子跑，结果里写明“没有资源上限：原因”；
- 默认内存上限 6 GiB（本机取一半和 6 GiB 中较小）、进程数 512，设置页能改；
- 检查撞上内存上限，自动返工的“请知悉”带上“调高上限”（决定 55，L16）。

**结果。** 2026-10-16 合入。合并树（dfe3cc9a 加本片）在 WSL、有 bwrap 和用户会话的全量里，432 个测试文件过了 431 个（7,125 项过了 7,124 项）。没过的一项是 2B 的旧测试 2B-09：取消的时机写死了，赶在闸门放行之前取消，命令按规定没跑。改成等文件写出来再取消，单独连跑 3 次都过。五个 RE1 文件在真机上一次一个跑，全过。实测每条命令多花约 9.5 毫秒（中位数），普通命令 150 次全部读全。没有调用真实模型。
