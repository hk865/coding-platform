## lead 对 Codex 第四次审查第 1 条的判断（不返工，记为已知限制）
Codex（`codex2/kBimplrev4.out.md` 第 1 条）指出：快照时 `.git` 是目录、选了只读绑定；挂载前别的写者把它换成普通文件，bwrap 照路径把这个文件绑上，命令能读到它的内容；另外 `:745` 的 IPC 遍历还会再 `lstat` 一次可读的 `.git`，`:822` 的运行时路径另行检查。

lead 判断不是必须修：
1. 能读到的只是那个写者自己写进 `.git` 位置的内容。工作区写者写的东西本来就能从别的路径读到；没有 Host 禁读的路径因此露出。
2. 文件形式的 `.git` 被盖成 `/dev/null`，是为了链接式工作树里 git 用不了（K 规格第 264 行、L17），不是保密。这次替换最多让 git 的表现和 L17 不同，不涉及禁读内容。
3. `:745` 的再次 `lstat` 只决定要不要往下找 IPC 端点。换成文件时文件里没有端点；换成另一个目录时会照常往下找并遮住端点，比只用快照更保守。
4. `:822` 的运行时目录是已有行为，计划里的 `.git` 挂载排在它后面，盖得住。

## 记进 STATUS“缺口”的已知限制
- 只读命令的受保护路径是按路径遮盖的：快照时不存在、命令运行中才被别的写者建出来的受保护路径没有遮盖（DSH 第 4 轮 UNSPECIFIED）。
- 按路径的遮盖假定命令运行期间没有别的写者改名或替换受保护路径（或它的祖先）；有的话，遮盖可能对不上新路径。今天没有会这样做的平台写者；彻底解决要按 fd 固定每个受保护路径，另议。
- IPC 端点的扫描有界（20,000 项、64 层），之外的端点不遮（M12）。
