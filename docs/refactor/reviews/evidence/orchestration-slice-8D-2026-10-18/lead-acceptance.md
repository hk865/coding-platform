## 已知限制

### 规格 §11.7 的列表

- **C/C++ 的系统头文件和 Python 的标准库、外部包都读作没解析**，按 L7 这些模块缺的依赖几乎都是 `unknown`。
- **C/C++ 只按一个平台读**：没写目标的数据库一律按 `x86_64-pc-linux-gnu`，预定义宏永远是 clang 的；只在别的平台编译的文件是 `skipped`（libuv 71 个文件、约 199 对引用、34 个目录对，`src/win` 整个是孤点）。
- **在别的机器上生成的编译数据库**（路径不在这个工作区根下）全部编译单元的主文件都不在观测的文件里，什么也不解析；用 clang 时 CMake 的预编译头会让那些单元失败。
- **合并以后，colcon 跨包要经被 git 忽略的 `install/` 才找到的头文件读作没解析**（SLAM 少 9 条）；嵌套的独立 CMake 项目进不了根数据库，文件是 `skipped`（libuv `docs/code` 34 个）；工作区根上没有数据库、几份又不合汇总或合并两种摆法时是 `有多个编译数据库`；根上有数据库时只用根上的，子项目的文件照旧 `skipped`；ROS 接口头和 rosidl 生成的头文件读作没解析；不 `#include` 自己头文件的 `.cpp` 在图上是孤点。
- **Python**：运行时才有的查找根读不到（脚本所在目录、改 `sys.path`；Django 的 `tests/runtests.py` 让 17 条项目内引用没解析）；多包仓库只读根上的配置（ros2/demos 4 条包内引用没解析）；没有扩展名的脚本不认领；往 `sys.modules` 塞的子模块和 meta path importer 在项目里有同名文件时读成 `是模块，不是包`；名字不是字面量的 `importlib.import_module`、`__import__` 看不到；中间各级的 `__init__.py` 不加边（Django 有 135 个包标记文件是孤点）；`sys.stdlib_module_names` 跟着运行扫描的 Python 版本走。
- **`complete` 只说明解析覆盖完整，不说明没有依赖**：SLAM 的 10 个 `.py` 全部 parsed、`complete`，边是 0，它们其实经话题、launch、参数文件全都连着。
- **§10 段自己的三条**：仍逐次读全部块、每次新观测读三遍材料（54 块约 265 毫秒是 8A 旧测量）；TS 的轻型扫描仍在 Host 进程里跑，内存跟冻结材料（最多 128 MiB）走，一次只留一个文件的语法树；严格捕获和 `project_index` 没有增加独立的 TS 程序预算（仍建不设上限的程序）。
- **实测的局限**：四个项目的 R2lex“0 误判”来自原型，第二轮没有新做故障注入；Python 只测 3.12，没量用 Django 写的应用项目。

### 运行时依赖的候选（做不做由你定）

成本是子 agent 的粗估，没量过；都要先有“引用的种类字段”。

- **ROS 通信图**（话题名当节点、带 launch 的上下文），价值最大：ros2/demos 99/103、SLAM 34/34；难点是同名端点多、`SkipFunctionBodies` 看不到函数体里的 `create_*`；中到大。

### 验收和测试上的已知限制

- **A-27 有一个扫描层的例子保留**：类型引用的行号。公开结果里没有未解析引用的行号，只能用扫描函数直接测；其余 A-27 的例子都经共享平台夹具、双后端。
- **`neighbors` 页不带被查文件自己的边**：页面只带页内节点之间的边，所以 A-18 的文件层断言是每个文件恰好一个后继（精确的唯一目标节点），不是页里的一条边。要改这个断言得改 `neighborsPage`，这一轮不改。
- **首轮的后页 `stale` 字段随翻页路径删除**，不再适用。**没单独断言的**：`ready.engineVersion` 没有写死断言（`engine` 断言成 `libclang`）；`语法错误`、`二进制` 是种类名，测试断言实际文本。
- **没有夹具的**：`拼写纠正后才找到` 实现了，但 libclang 18 上找不到能触发的写法，没有测试；自己到自己的边没有协议夹具（两个真脚本在发出前就丢掉 `from == to`，A-22(m) 覆盖尖括号退路找到自己）。
- **接受的容错**：末行没有换行、字节相同的重复 `ready` 仍接受（没有拒绝规则）；不是 `Error` 的抛出按 `typeof` 记；`RecursionError` 夹具用 10,000 层嵌套（2,000 层在 3.12.3 不抛）；`ready` 之后中途 `failed` 当作整门语言失败（顺序没有明文规定）。
- **决定 79 之后不再测旧格式**：旧正文、旧块、旧 `inventory` 都由解码拒绝，只留一条纯解码反例；A-16 的夹具和生成器删了。平台入口读 8A 之前旧观测的 `notCaptured` 也一起删了。
- **首轮回报的 250 个 TS 文件“不在 TS 分析的范围里”**：范围外文件仍记 `skipped`；返工 1 的测量是 1,409 个 TS/JS 文件、1,162 个 parsed，不能沿用 250，也不能直接归因于默认根过滤。
- **严格捕获的关系上限保护分支**没有被直接覆盖；关系超量已有捕获阶段测试，无需为保护分支造不可达状态补测。
