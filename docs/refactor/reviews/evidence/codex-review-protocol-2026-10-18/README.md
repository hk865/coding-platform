# Codex 审查流程的依据（决定 80，2026-10-18）

用户问怎么用 Codex，才能一次查全、两三轮返工收住，而不是 K3 第 4 组 B3 那样返工 8 轮。lead 跑了两个多 agent 流程（Claude 子 agent，只读）：

1. **根因**（[root-cause-k3-b3.md](root-cause-k3-b3.md)）：逐轮把 B3 的 75 条必须改分类（生产 17 条，都在返工 2 之前；测试 58 条，每轮 5–9 条不降），比较了换实现者（Opus 子 agent、Codex）和冻结清单几种做法。
2. **用法设计**（[protocol-design.md](protocol-design.md)）：三个方案（一次全审、先定合同、机器检查），各拿 K3 B3 和 L8 的历史回放，判断哪些问题能在第一次全审里查出来、要几轮；最后综合成一套。综合部分的第 3 节是四个提示词模板（全审一组文件、同类扫查、返工复核、任务书审查），第 4 节是要加的脚本。用户 10-18 同意采用，记成决定 80，中文做法在 [DSH-WORKFLOW §7.1](../../../DSH-WORKFLOW.md#71-codex-审查流程决定-80)。

两份都是流程的原始输出（英文），里面的轮数和概率是回放推演，不是实测。
