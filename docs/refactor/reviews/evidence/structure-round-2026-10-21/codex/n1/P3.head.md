# Structure round night 1, part P3 (S3 / D3a: pack format, renderer, platform pack v1, build and checks)

Your part is `P3`: `./.lead-ref/parts/P3.diff` and `P3-files.txt` (`src/contracts/prompts/*`,
`scripts/build-platform-prompts.mjs`, `scripts/check-boundaries.mjs`, `package.json`, `runtime-assets.json`,
`resources/prompts/platform/pack.json` and `strings.json`); base `./.lead-ref/base/`. The book §5.1 rulings 1–4, 8
(the renderer's part), 11; the frozen spec's §0.4 first bullet, §1 first bullet, P1, P10 and §2; the inventory
`inv-d3.out.md` §2 (templates, slot tables, the seven adaptation rules) and §5 (assets); DSH's reply
`replies/s85-reply-S3.md` §3, §4. The templates and tool files are audited in P4–P6; read them here only for the
generated module and the checks.

**Look hardest at:**

- **Types** in `prompt-pack.ts`, `slot-tables.ts`, `render-template.ts` against the book's code block (ruling 3) and
  the spec §2: every field, `readonly`, the renderer signature.
- **The renderer** against spec P1 and rulings 3 and 8: only the three constructs; slot values never parsed (a value
  holding `{{x}}` or `{{/x}}` renders literally); the four code-bug throws (unknown template, undeclared slot, a slot
  used twice, a required slot `undefined` or `''`) and nothing else throws; an optional empty slot renders nothing and
  drops its block; **a whole-line block marker removes only its own newline** (ruling 8) — DSH's reply §3 says it
  also removes the marker's indentation: is that what the book and the spec say, and does any v1 template depend on
  it?; `sectionRanges`: one entry per slot that rendered a non-empty value, UTF-8 byte offsets, end exclusive — for a
  block slot, does the range cover what the spec says it covers?; `finalToolNames` read only by tool blocks. Walk
  inputs with multi-byte characters, `\r\n`, an empty block body, adjacent markers and a marker at the end of the
  text.
- **The slot tables:** all ten tables of inventory §2, including the three S4 tables (`work-input`,
  `query-planning-input`, `query-copy-input`), against the inventory's slot lists and required flags.
- **The build script and the generated module** (ruling 1): paths from the script's own URL; the module exports
  `PLATFORM_PROMPT_PACK_V1` as `{ … } as const satisfies ResolvedPromptPackV1`; how every string is escaped into the
  TS literal (backticks, `${`, backslashes, quotes, `\r`, `\n`, non-BMP characters) so the value equals the file's
  bytes; deterministic order; does the committed module equal what the script generates from the committed resources
  (compare a sample of templates, strings and tool texts byte for byte, and the key sets in full)? No fs I/O, no
  `await`, no Host settings at run time.
- **`pack.json` and `strings.json`:** the manifest against spec §2 (templates with `file`, `version`,
  `mentionsTools`; `strings`; 31 `tools`); **duplicate keys in `strings.json`** (JSON keeps the last one silently);
  keys no code reads, and code that reads a key that does not exist (would it fail the typecheck through the literal
  types, or yield `undefined` at run time?).
- **The checks** (ruling 2): one raw-byte SHA-256 entry per pack file in `runtime-assets.json` (40 files; hash a
  few and compare); `inspectSourceTree` gains only a closure check that works on the directory it is given (the
  boundaries test copies `resources` and `scripts` but not `src`, `tests/architecture/boundaries.test.ts:18–58`);
  the "generated equals generated now" check only in the CLI branch (`scripts/check-boundaries.mjs:533` of the base);
  `package.json` gains exactly `node scripts/build-platform-prompts.mjs --check` in front of `build` and nothing
  else (SC's `test:scale` untouched).
- **Import direction:** `src/contracts/prompts/*` imports nothing from `src/core` or `src/app`.
