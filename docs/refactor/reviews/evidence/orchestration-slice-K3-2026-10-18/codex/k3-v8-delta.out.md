1. **批准的方案仍可能被拦。** §1 L19a 说“方案命令不拦”，§5.2 B2-02 要求方案照跑；但新规则逐动作比较，没有方案放行分支。例如批准的 `backup && migrate` 包含被拦的 `migrate`，仍会被拦。**最小修正：**明确已批准方案原文与 (A)/(B) 的优先级，并同步 B2-02，避免重复求批准。

2. **注明过的新写法可能根本没存下来。** §1 L19a 保证注明后即纳入拦截；§3.2b 却规定返回 `pending/refused` 不写记录。已有请求时再注明另一种静态认不出的写法，只回旧请求，新写法随后仍能直接运行。**最小修正：**明确这些分支如何持久保存新增写法及其归属，保持不新增卡；钩子和再次申请共用这份映射。

3. **允许未用时，再申请的行为矛盾。** §1 L19a、§5.2 B2-12 允许“人答了以后再请求别的写法”；CRR-01 也只检查 `pending/denied_final`。但 §3.2b 不变量禁止同一出处同时存在 `allowed` 和 `pending`。**最小修正：**定明允许未用时再次请求的返回值及旧允许的处理，同步不变量和测试。

4. **核对记录身份没有贯穿接口。** §1 L19a、§2 工具入参已用 `rewriteOf:{review,alias}`，但 §2 `requestRerun` 仍是 `rewriteOf?:string`；准备清单的 `blockedCommands` 也没有 `reviewRef`，接续说明仍只列 `#别名`。不同核对记录的 `#1` 无法可靠对应。**最小修正：**统一类型，在跨记录传递和显示处带上核对记录身份。

5. **动作规范化丢失参数边界。** §1 L19a 静态解析第 4 条会把 `tool 'a b'` 和 `tool a b` 都变成 `tool a b`；两者参数不同，却会被 (B) 当作同一动作，违背决定 68“拿不准时不多出卡”。**最小修正：**保留参数边界，例如用词数组的确定性编码作比较键；显示文字另算。

6. **脚本目录与“一次读一个文件”没有闭合。** §1 L19a 支持递归组合命令及前置 `cd`，但 `cd a && npm run x && cd ../b && npm run y` 涉及两份文件；钩子最多读一份，§2 又只有一个 `scriptBasis`。此外，请求工具没有 `cwd`，未定义它按哪个目录展开。实现者必须猜选哪份文件。**最小修正：**明确目录作用域、请求时的目录来源及多目录退化规则，并使依据字段与读取上限一致。

7. **卡片要求显示的命中依据没有保存。** §1 L19a 要卡上显示命中的动作；§2 请求记录只新增 `alias/declared`，没有命中动作或当前脚本展开快照。例如申请 `npm run Y` 时通过当前脚本命中，出卡前文件改变，就无法重现当时依据。**最小修正：**创建请求时保存有界的命中方式和动作，卡片直接读取，避免重新展开。

8. **(A) 和允许判断写成了文字与摘要比较。** §1 L19a、K8-6、§3.2b CRR-03 都写“规范化文字等于 `commandSha256`”；§2 又明确该函数输出 SHA-256，请求字段注释却称其为文字。照字面实现会永不命中。**最小修正：**统一为双方规范化后的摘要比较，修正字段注释。

9. **新增数据破坏了必须写入的容量保证。** §1 L19a、§2 新增完整动作、脚本正文和展开结果，却未调整 §1 L7 的预留预算；L7 仍保证处置、批准必定放得进 512 KiB。现有工作区读口默认可读 2 MiB（`src/core/workspace/workspace-tools.ts:7`），且调用必须指定 `maxBytes`（`src/core/workspace/ports.ts:90`），稿中没有规定取值。**最小修正：**给新增内容明确总预算和超限退化规则，计入记录及准备清单预算，不能让静态展开阻断处置。

10. **决定 69 的成本行不可按现有读口兑现。** §1 L19a K8-6 写“一次索引查找＋一次批量读”取得任务全部请求；实际查询每页最多 200 条（`src/core/record-store/lookup-index.ts:175`），查询内部已经读取并返回记录（`src/core/record-store/sqlite-record-store.ts:604`）。请求历史又没有总量上限，按稿实现会漏页或重复读取；§2 `listRequests` 也缺少仅按任务查询的分支。② 的成本行则只列 Kernel 和文件读取，未交代存储读取上界。**最小修正：**补齐读口，按页数、记录数写真实上界，复用查询结果；把 shell、允许消费及②落实各分支的读取次数写成验收行。

11. **新增测试仍挂在无法观察相应行为的入口。** §5.1 明定 R5 是纯状态转换，D11 已说明它看不到存储、组合和正式重放；§5.2 B2-11～15 却要求从 R5 验证文件读取、出卡、shell 放行和 Kernel 重放。B2-10 还把“全无关段时退回整段文字”归给解析函数，而 §1 L19a 将它规定在保存 `blockedCommands.actions` 时。**最小修正：**涉及持久化和执行的断言挂到 R4 的公开 owner／Work 场景；B2-10 分清解析结果与保存时的回退，避免测试替实现补规则。
