## Lessons for writing tasks for DSH

1. **Flash can do judgement on an owner-service write when the repository holds the pattern.** 5/5 passed with no case list, finding the sibling service and the implementation notes by itself. Cite the pattern file and the notes in the book: it costs one line and makes the lookup certain.
2. **State cross-cutting conventions as rules; "follow the code base" loses to a literal spec.** 5/5 left out the workspace refusal and 5/5 the empty-source refusal, because row 5.5's refusal order did not list them. For task D: write every invariant you expect as a sentence, for example "every specifier you do not need to change stays byte-identical" and "no file outside the move table changes". Do not count on DSH inferring it from neighbouring code.
3. **Read UNSPECIFIED as the place where the judgement calls are.** 4 of 5 runs named the workspace choice there, so a lead could fix it with one guided round without any tests. Trust its claims but not its silences: the detailed run's thorough self-review did not name it. To make silence meaningful, ask an effect question, for example "for each value you pass to the machine, name the line of the machine that reads it".
4. **A reading list by line ranges plus a capped test step is the cost lever.** −66% tokens here; L4, L5 and L5b showed the same. Tokens grow with steps × context, and whole-file reads plus whole-directory test runs are what make both large. Name the one test file to run and its count, and forbid whole-directory runs when they test nothing of the task.
5. **Feedback must point.** The raw green output gave "complete" in 2 s, now at 7 levels. The guided review fixed both gaps in 89 s, using the code base's own texts. It had a location (file:line in DSH's diff), the precedents by file:line, the book's rule quoted and a scope fence. For task D: compare DSH's `git diff --name-only` and counts with the expected ones, then send the differing files with line numbers and the rule sentence, never the fix.
6. **Role framing: drop it.** **Pro: do not use it** for these tasks; it was slower and missed the spec rule that flash found 4/4.
7. **Discipline.** `/tmp` was used in 4 of the 6 flash tool-using sessions despite "stay inside the current directory", and one report then denied creating files. Keep the sandbox, or allow a named scratch place, and check every "no files" claim.
8. **For task D**, L6 changes nothing in the L3 plan; it confirms it. Use the detailed book with the exact counts and the keep rule (L3), a reading list, a capped verification step and the forbidden git commands by name, and have guided review rounds ready. The ladder has not found flash's upper limit: L2 through L6 all pass, with a wrong-rule failure only at L3 (fixed by the detailed book).
