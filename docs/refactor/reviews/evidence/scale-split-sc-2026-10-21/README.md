# 规模测试拆分 SC（决定 86-6，2026-10-21）

**结论：** 合入（2026-10-21，`66582273`）。用户 10-21 定：“按你的建议拆，规模批每片合入前跑”（HANDOFF 决定 86-6）。

## 做了什么

- **机制：** `tests/**/*.scale.test.ts` 从日常配置排除，由新的 `vitest.scale.config.ts` 收集；`npm run test:scale`
  用一个进程跑，每片合入前和全量一起跑一次。`npm test` 和 CI 不变。
- **页宽接缝**（默认值就是原常量，生产不传；没传的宽度一路不传到 owner，由 owner 自己的常量决定）：A
  `lookupAll`；B 决定读模型的 `sourcePageLimit`、`lookupPageLimit`（也到 Goal 列表、用户消息和候选查找）；B′ 两个候选
  枚举；C 规划问题读取；D 重跑请求服务（钩子读和请求工具两条）；E 自动返工的有序读；F 上下文扩展的决定页；G 未送达
  回复；I 工作线读取里 200 宽和 100 宽的读到底循环。不做 H（QA-17 不拆）。
- **拆分：** 盘点里最慢的 12 个文件。原规模的用例原样挪进同名 `.scale.test.ts`（尺寸、后端、断言、超时都不变，不注入
  页宽）；日常文件里是同一组断言的小版本：两种后端，经 owner 依赖传小页宽，每层读取至少跨两页、决定那一条在最后一页，
  每层的顺序和分页手算写在注释里。
