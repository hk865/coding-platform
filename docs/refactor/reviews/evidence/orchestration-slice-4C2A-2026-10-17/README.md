# 4C-2 A 段的执行证据（2026-10-17）：装配、“该更新”和书记提醒

**是什么。** [第 4 片规格](../../../design/orchestration-2026-10/slices/slice-4-SPEC.md)的 4C 第二轮（§11.9）分成两段，这是 A 段；B 段（注记卡和它的落实、证明事件、“请知悉”，L17、U3、U6、U7、U9）另走。施工和验收中定下的读法见规格 §13。
- **装配（L20 按 §11.4 改过的样子，决定 72 的 U8）：**
  - 上下文的 `notes` 分成 `understanding` 和 `general`：
    - `understanding`：项目、目标、阶段三行，项目行带全文，再加项目规范；
    - `general`：一般注记的索引行，按本次调用的来源和来源类别排序。
  - 一个取记忆材料的函数，一次装配一个读取窗口；查询类装配只拿 `understanding`。
  - 每行都带注记号和版本，上下文记录只列渲染出来的注记行；绑定的执行重放时不重新装配。
- **“该更新”（§11.5）：** 从目标的现行计划读触发（任务完成、取消或取代、返工、归档、采用计划），和当前理解的基线比；核对在一次调用里按目标只读一次触发；`understandingOf` 自己的指针读删掉了。
- **书记提醒（L16，U10）：** Host 的每个工作区一条检查：
  - 待审数到 10、该更新数到 5 时提醒；有一条没人认领的归档返工时立即提醒。
  - 收件人是 `sessionId` 最小的项目书记，一条消息带幂等的请求号。
  - 每个收件人最多一条没处理完的提醒，重启以后也成立。
  - 账本游标没动就不重算，没发成功的下次重试。
- 验收行 C-01–C-04、G-01（装配部分）、PU-03、M-12a–h、D-03、D-10、D-15（提醒部分）、D-18，测试入口 NE5、NE6。
