## 4. Rules (from the spec §8 and book part 1 / part 2; each applies to every group)

1. Public `GraphWrite` keeps its `expected` pins inside the fingerprint; a replay returns the original event's value
   and cursor, never the current record (`sessions/session-lifecycle.ts` `identityKeyOf`, `recheckLifecycleAfterMiss`).
   Internal archive steps derive their identity from the stored request (`deriveArchiveStepCommitIdentityV1`, §2.3).
2. State purity: `src/core/work-graph/state/` imports only `src/contracts/` and `state/`; no clock, random, timer,
   process, network; time comes in as `now` from the owner. All state transitions go through `state/` (the
   state-writes test enforces it).
3. Session facts reader is `tasks/session-facts.ts` (implements `SessionFactsPort` of `model/session-facts-contracts.ts`);
   `sessions/` and `queries/` never import `tasks/`; they get the port injected (same instance from
   `create-platform.ts`). Without injection the new sessions entries return `unsupported`; queries keep old behaviour
   (§0.2 L1). No codec moves. No new module edge; do not edit `docs/refactor/module-target.json`.
4. Old records lack the new optional fields and decode with the §2.9 defaults; stored bytes, digests and receipts of
   old records do not change; a present but malformed new field is refused (`invalid` at an entry, `unavailable`
   from a stored record), never replaced by the default (K3).
5. No `replyDeadline` (L2). A transfer keeps sender, recipient, body, status and response of the message.
6. No anchor without an execution (L3); at most one anchor per Run; anchors are immutable; "picked up" is derived
   from later `inputBinding.anomalyAnchorRefs` plus a real entered fact (T7).
7. Waiting is not idle: a stored but unconsumed reply is still a wait. An archive request, a copy provenance or a wait
   excludes a Session from new Work and Query claims at every claim entry, not only in `chooseSession`.
8. Stop is not success (D6, D7); a Query is never cancelled or paused by an archive (IT14); an archive never
   completes a Task, never starts a check, never reverts files.
9. A composite failure is not zero writes: when a later step of `archiveLine` fails after earlier steps committed,
   return `ready` with `state:'partial'`, the committed receipts, the original rejection and the exact message
   `处置已完成，归档没成功` (IT13). Never undo a committed step.
10. The rework cap exemption is narrow: only a stop caused by this archive request (its cancel, its wait cancel) or a
    real `interrupted` fact of that Run counts as `interrupted` and is not counted (UT32, UT33, SV35, SV57); a forged
    or unmatched archive origin is refused `forbidden` (UT34, SV36, SV48, SV49); an ordinary failure before the
    retirement keeps its class and count (SV59). Earlier human pause / cancel fences keep their meaning (UT35, SV37).
11. Maintenance starts nothing: no timer, at most one page per call, no model call, no Kernel start, no check.
12. Changed files are honest: Kernel-confirmed → `confirmed`, the rest → `possible`; worktree fallback puts all in
    `possible` with `runBaselineKnown:false` and the mixed-ownership warning; nothing readable → `unavailable` with a
    reason, never an empty "no changes" (IT01, IT02, IT32, SV27).
13. Soft ordering is not a gate (§4.3): `orderTasksByDependency` only reorders; `claim-service.ts` gets no
    "upstream satisfied" check.
14. Do not change exported signatures that part 1 wrote (they are what the frozen tests import), except to fix a
    real conflict with the spec; such a change is made only by the main Session (section 6) and reported.
