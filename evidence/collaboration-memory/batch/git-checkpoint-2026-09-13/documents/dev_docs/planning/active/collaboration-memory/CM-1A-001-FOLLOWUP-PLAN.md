## 第 1 步：修复账本校验，让合法提交能通过、非法提交被拒绝

| 项 | 要求 |
| --- | --- |
| `participation-start` | **先**通用事件校验，**再**专用校验。补回**事件版本（schemaVersion）**、**非空 eventId**、**作用域一致性**；保留事件顺序、快照与 expectedVersions 的关联约束 |
| `communication-route-page` | 明确区分两个 intent 角色：①本页已完成的 intent（必填、恰好一个）②可选的下一页 pending intent。**分别**检查版本、**确定性 ID**、**来源位置**、**分页边界**，并允许相应数量的 `CommunicationIntentRecorded` |
| `waitRef.workId` | **保留删除该字段要求的修复**；Work 归属继续从 canonical 快照核对 |

**完成条件**：现有非法事件反例被拒绝；**超过一页的真实订阅投递能够连续完成**。

## 第 2 步：统一 Work、参与关系与后继身份（解决换手与 R7）

用户裁决：**后继始终使用 admission 中明确记录的 WorkRef**。普通任务仍可按 `(goal, task)` 解析工作身份；
**已经受理的协作后继不得重新解析成另一个 Work**。

| 项 | 要求 |
| --- | --- |
| Work 权威状态 | 维护**当前参与关系**，由 Control 原子更新；同时增加 **AgentInstance 的 active participation 唯一约束** |
| Wait | **保留注册时的参与关系用于追溯**，但**接续资格由 Control 根据当前有效参与关系、RoleBinding、前驱结束状态重新判断** |
| 后继 admission | **原子固定**本次采用的参与关系与授权版本；**派发与 Context 都消费这份结果** |
| 调度触发 vs Agent 工具 | 调度触发使用 **system 身份 + 来源关联**；Agent 工具调用使用**真实 Run 的 exact principal**，**避免把新参与者与旧 Run 拼成一个身份** |

**完成条件**：旧参与段结束、新参与段建立后，等待**仍能产生同 Work 的唯一后继**；**无有效参与者时保留等待并给出明确原因**。

## 第 3 步：接通 Host 工具与后继 Runtime，形成第一条完整正常链

| 项 | 要求 |
| --- | --- |
| 窄 Adapter | 在**应用组合根**注入，提供请求、回应、订阅、all-wait、取消；**身份由宿主绑定，模型不能自行填写或替换 principal** |
| body-first | 正文**先存 Vault**，再经 Control 正式受理；工具**只有拿到提交回执**才能报告受理成功 |
| RunSpec 可重建 | 为后继保存**计划与指派版本、指令来源、授权、运行配置**；**不要只保存在测试或进程内存里** |
| 后继启动 | Dispatch 消费后继 outbox 时，**通过既有 `RuntimePreparationPort` 完成可重放的准备**，再正式启动；重启后从持久事实恢复；**已经运行或结果未知的 Run 不重新启动** |
| Context 选材 | **只按 admission 固定的 Delivery 集合**取材，其他可选材料由既有 Context 规则选择 —— 不把整个邮箱当成本次必需输入 |

**完成条件**：**删除测试中的手工后继 `prepare`**，通过真实 Host 工具完成「请求→报告→等待→后继→模型输入」，**重启后也成立**。

## 第 4 步：补齐持续路由、调用证据和故障恢复（覆盖 R1–R5）

| 部分 | 方案（用户逐字） |
| --- | --- |
| 持续路由 | 可路由事件与待路由 intent **同事务登记**；持久记录**源事件位置**、**固定订阅范围**和**当前订阅分页位置**。同一事件的**订阅翻页**与**跨事件推进分别处理**，**末页完成后才推进事件处理位置** |
| 调用证据 | 在实际 `ModelClient.stream(request)` **边界**计算请求摘要；Control 复核 exact Run、材料版本及授权后**签发一次性许可**；Runtime 将**调用尝试及结果**经正式事实通道落账。**provider 的可验证回执才记 ack**，**计量完成不直接等于 ack** |
| 取消与 unknown | **先持久化取消意图**，再调用执行能力。明确区分**已完成 / 已证实无副作用可重试 / 确认取消 / 无法确认进入 quarantine**。**只有已证实无副作用的失败才能进入退避重试**；**租约到期不构成重跑依据** |

**保守恢复原则（用户强调）**：外部调用与本地账本之间无法原子提交的窗口，**结果不明就对账或隔离，不能自动再调用一次**。

## 第 5 步：实现有界并发，然后统一收尾

- 在**唯一 drive 内**加入**有界执行并发**，使两个只读 Run 可以**实际重叠**；写入仍受既有 Workspace lease 约束。
- 补齐 `availableAt`、**退避**和**公平选择**，输出 **backlog、最老等待项及阻塞原因**。
- 用**独立 SQLite 连接和进程**证明：只有当前领取者能有效启动，**重放 start 不再次调用副作用端口**，**旧 generation 无法覆盖新结果**。
- **同步直接修改的 Interface**，生成**包含逐文件哈希、准确差异和构建来源的新快照**。
- **原指纹不一致的问题保留记录**，用**统一脚本**解决后续可复算性。
