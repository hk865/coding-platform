## 1. 范围与可观察交付

贯通同一 Project/Workspace 内：

```text
已受理 Work 的 Host 协调工具
  → Work 定向请求 / Subscription / all-wait
  → Control 受理 + Ledger 持久状态与 intent
  → Dispatch 持久领取 / 分页路由
  → 条件及前驱结束资格满足
  → 唯一 successor TaskAttempt / Run / Task outbox
  → Context 选材 / 绑定 / 提交前授权
  → 实际内核与 ModelRequest
  → 公开结果 / 调用证据 / 可恢复状态
```

交付的不是只有类型或 CRUD 的框架。应用组合根必须能受理／唤醒这条路径，真实持久宿主能够运行与重启；可以通过窄的已有服务/Host 入口及可重跑样例展示，不要求完整图形界面。故障注入可以在隔离 harness 中进行，但其生产者、受理命令、存储、调度、Context 与 Runtime 必须复用产品路径。

推荐正常场景：沿已接受 Plan 建立协调 Work C 和两个只读调查 Work A/B；C 经 Host 工具发定向请求、订阅有界报告并等待 all。A/B 使用现有 WorkspaceReader/source pin 读取授权本地材料，报告 body-first 保存后正式登记。C 的前驱 Run 公开结束，报告到齐后产生同一 Work 的唯一后继执行，实际模型输入包含精确报告版本，输出可核对 nonce/version。另设授权订阅者与无权 Work，验证共享正文与权限隔离。

本票建立 Request/Subscription/Delivery/Wait 所需的最小身份与正式 principal；AgentInstance 仅负责归因，Work 是持久责任地址，RoleBinding 固定授权版本。首条范围同一 AgentInstance 至多一个 active participation；同一 Work 的前驱与后继不重叠执行。

### 明确不在本票内

小记忆保存与维护、profile scope、主界面秘书/参谋完整对话、架构决定完整前端、结构化知识库、自动画像/提炼/Skill 演化、第二领域产品证明、远程 broker/Worker、同 Run 热恢复、通用工作流 DSL。

本票只做 all-wait 与 timeout/cancel；any-wait 的首个实际消费者与剩余通信由 PLAN M06 后续实现，不以本票 PASS 代替 V04 全部覆盖。Query/Reviewer/Handoff 完整迁移属于 M02/M03，不强塞进首票，但本票的共存边界和不重复调度必须有证据。
