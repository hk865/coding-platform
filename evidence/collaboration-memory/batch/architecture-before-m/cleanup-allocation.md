# M 准备：整理项分配与证明

| 票 | 同期整理 | 完成证据 |
| --- | --- | --- |
| M01 | ordinary 与旧 parallel 生命周期收敛；Host 不串行阻挡独立只读执行；共享 outbox 选择/积压规则；区分对外 drive 与内部执行；清理相关旧票号/冻结注释 | 旧生产入口去向/调用者列表；不同 wake 下两个真实调用重叠；单次有效启动；scope/limit/延期公平；源码差分分别列组织和行为 |

| M04 | 规划与 Rework 的 Host 编排下沉为有明确职责的内部模块；旧 Lane/票号名称改为当前行为 | 同一受理/触发重放无新增计划；丢失 wake 后从持久状态恢复；无 Verification→Dispatch 导入 |
| M05 | 各 queue 只剩可解释的局部互斥；扫描/wake/close/cancel 的责任统一；收齐 production harness 命名/测试适配去向，完成触碰区术语注释复查 | 每队列三问答案、停用入口清单、全 M 生产消费者、旧库/并发/取消/退出恢复 |

公共验收：同一规则是否只维护一处；外部调用方是否少了解步骤；同一修改是否更集中。只转发而不隐藏复杂性不算收益；多个布尔开关维持不同授权的万能函数不算复用。小模块无需强制分目录。

注释必须同步：删除/更新失实的“暂不支持”“冻结不能改”“待某 lane 实现”，保留不变量与原因。历史票号放证据，不删除历史原文。持久事件/字段/表和外部协议改名须单列兼容，不做全局替换。

性能：对本次触碰的 outbox 查询/积压及新增投影记录读取次数、返回规模、耗时和增长趋势；必要时记录内存。优先减少无关扫描/解析，保留 SQLite 事务与选择优势；共享规则不得强制全库载入内存。若出现缓存需求再作独立决定，当前不引入 Redis。性能数字仅覆盖固定夹具和环境，不替代实际用户规模测量。

范围外登记：协调/等待 3000 行整体领域重组、历史读模型双适配器大规模投影收敛、全 contracts 搬家。与 M 新修改相邻且影响正确性的部分仍必须处理；其他项不借本批全仓改写。

M 完成后的范围补充：上述登记仅限定 M 票实施范围，不表示整批已完成这些整理。用户现明确要求继续全范围检查及必要重组，由 [M 后结构整理计划](post-m-cleanup-plan.md) 承接，安排在 I01–I04 前；不预设所有 contracts 都需要搬移。

中间定向验证，计划内修改完成后固定源码集中回归；独立验收只对精确快照。I01–I04 仍核实际集成版本，不能拼贴单票 PASS。
