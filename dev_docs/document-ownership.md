# 文档职责与权威关系

本文件是文档职责划分的唯一规则来源。职责表示默认维护和裁决责任，不是文件访问权限；人和 Agent 共用规范正文。

## 职责划分

| 材料 | 日常维护者 | 人类参与边界 | 权威范围 |
| --- | --- | --- | --- |
| PRODUCT | 人主导，Agent 协助编写 | 产品承诺、范围与非目标 | 产品结果 |
| ARCHITECTURE | 人主导，Agent 协助编写 | 分责、边界及重大架构取舍 | 总体结构与全局约束 |
| evaluation/mvp-scenario | Agent 维护，人审阅标准 | 成功标准和覆盖范围变化 | MVP 验收要求 |
| planning/ROADMAP | Agent 维护，人管理优先级 | 阶段范围和优先级变化 | 阶段计划 |
| interfaces/completion-policy | Agent 维护，人审阅关键行为 | 完成、取消、部分接受等语义取舍 | 完成行为规范 |
| CONTEXT | Agent 维护 | 产品含义发生歧义时 | 领域词义 |
| modules、其余 interfaces | Agent 维护与技术审查 | 超出授权或改变产品承诺、重大边界时 | 局部设计与跨模块契约 |
| decisions | Agent 记录实际决定及理由 | 需要人裁决的取舍 | 决策历史，当前约束落实到对应规范 |
| planning 下的 DAG、Ticket | Agent 维护 | 阶段审阅或未授权范围变化时 | 施工范围、次序、局部验收 |
| verification | Agent 维护 | 按需抽查证据或解决外部事实 | 验证程序与执行证据 |
| design 下的展示图与候选复核 | Agent 维护 | 设计选择待决时审阅，其余按需阅读 | 正式文档的投影或尚未接受的候选方案 |
| product 下的原始表达、双方对话与 archive | Agent 保管来源，维护推导索引 | 追溯时阅读 | 来源与历史；历史 Assistant 回答不是现行规范 |
| README、human、AGENTS、agent 入口 | Agent 维护 | 工作方式调整时 | 导航和执行流程 |

人主导不要求人亲自写文件，也不要求文字修订重新审批。现有明确授权覆盖的同步、勘误和实现细化由 Agent 完成；需要新的业务选择或授权时，提交具体差异和影响供人决定。

## 权威关系

PRODUCT 定义产品结果，行为规范定义语义，ARCHITECTURE 定义分责，Module 与 Interface 定义局部机制和契约。Ticket 消费这些约束，不得凭局部验收改写产品承诺或削弱正式契约。

规范冲突由 Agent 记录并提出修订。依据已有决定能够解决的直接同步；缺少业务选择的部分等待裁决，独立工作继续。

两个角色入口链接同一正文。Ticket 首次提出的长期规则，在契约冻结时落实到正式规范；当前实现不能只靠历史 Ticket 理解现行规则。

## 目录与生命周期

- `human/` 保存人类审阅路由；`dev_docs/agent/` 保存 Agent 维护流程。
- 现有规范保持稳定路径，两个入口按职责访问。
- 已完成计划可进入 `planning/completed/`，迁移时同步引用。
- 被替代的正文进入 `archive/`；兼容旧路径时保留 route-only 跳转，已有归档快照保持原样。
- 状态、批准和证据在负责的文件记录，导航通过链接查询。

变更传播见 [Agent 维护流程](agent/README.md)。目前由 Agent 执行影响审查，检查脚本验证结构；尚无自动语义影响分析或版本失效拦截。
